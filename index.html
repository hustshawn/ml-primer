激活值 / Activation可交互 · 显存计算器

权重是石头
激活值是水

前向路上每一层算出来的中间结果就是激活值 —— 它不在 checkpoint 里，却常是训练时最占显存的一块。四块显存里只有它随 batch × 序列长度长。把一层摊开数出 18 个张量，顺带解掉 activation checkpointing、FlashAttention、KV cache、W8A8 里的那个 A。

Attention / Head可交互 · 热力图

Attention 是什么
Head 又是什么

attention = 一次由内容决定的加权平均（权重当场算，不是训好固定的）；head = 同一件事并行做 8 遍，各用一套标准。顺带讲清 MHA / GQA / MQA 改的是哪个轴。

最后是训练

给已经懂推理的人补上训练侧。顺序大致是从小往大：先掰开最基本的计数单位，再看训练一圈是怎么转的、那些名词分别落在模型的哪一段人生里，然后是最常用的微调方法和多卡怎么分工，最后落到「这活儿到底要几张卡、跑多久」。

Epoch / Step / Batch可交互 · batch size 切换

训练就是
刷一本习题册

一道题 = 一条样本，一叠题 = 一个 batch，做完一叠改一次参数 = 一个 step，整本刷完一遍 = 一个 epoch。带一个能跑的 100 题动画：调 batch size 看 step 数怎么变，以及为什么日志横轴上的 global step 跨 epoch 不归零。

LoRA / QLoRA可交互 · rank 滑块

底模一个字不改
只训旁边那块补丁

LoRA 不是一个训练阶段，是「哪些参数有梯度」这一层的选择。机理只有一个加号；省的是优化器状态，不是 activation；推理要么 merge 掉换零开销，要么留旁路换热切换。
数据并行 / DP可交互 · 卡数滑块

模型复制 N 份
数据切成 N 份

名字里的「数据」就是被切开的那个东西 —— 复制的从来是模型。一步只有一个同步点（all-reduce 平均梯度），DP 一个字节显存都不省；推理侧没有梯度，它就退化成多副本 + 负载均衡。
资源估算 / Sizing可交互 · 显存 / 工期估算器

「要几张卡？」
这问题没法直接答

它不是一个问题，是显存 / 算力 / 互联三个约束的交集：显存定下限，算力定工期，互联决定能怎么切。两个联动的估算器 —— 拨模型和 ZeRO stage 看每卡显存分解与卡数下限，拨 token 量和 MFU 反算工期。重点是先搞清该问什么，再算。
