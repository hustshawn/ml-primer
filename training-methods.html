四段各自在干什么

每张卡先说明训练信号和数据形式，再列出属于这一阶段的常见方法。

① 预训练 PRE-TRAINING · 自监督

从大规模文本中预测下一个 token，根据预测误差更新权重。
训练数据长这样 —— 就是普通文本，没有任何标注

训练数据不需要逐条标注地理、语法、编程或推理知识。模型在持续预测下一个 token 的过程中逐步学到这些模式。

监督信号文本自己
人的参与只筛数据，不标答案
时间几周 ~ 几个月，几万张卡
产物Base 模型：会续写，
不会听话
这一格里的各种方法
因果语言建模 CLM

猜下一个字。GPT、Llama、DeepSeek 等许多主流生成式模型使用这个目标。

掩码语言建模 MLM

做完形填空（BERT 那一派）。常用于向量、检索、重排、分类和 token 标注等理解任务。

继续预训练 CPT / DAPT

拿别人训好的 Base 模型，继续喂大量领域语料（医疗、法律、代码、中文）。它适合系统性吸收领域分布和大量语料，但不是唯一能写入新知识的方法。

中期训练 / 退火 Annealing

在预训练后期减少低质量网页，提高教科书、数学和代码的比例，同时降低学习率。它用较小的追加成本调整训练末期的数据分布。

长上下文扩展

用长文档继续训练，并调整位置编码相关设置，把上下文窗口从 8K 扩到 128K / 1M。通常安排在预训练后期。

② 监督微调 SFT / INSTRUCTION TUNING · 有标准答案

用示范问答继续训练，让模型学会按指令生成回答。
训练数据长这样 —— 成对出现，答案是人写的
输入（人问）
用三句话解释黑洞。
目标输出（人写的范文）
黑洞是引力大到光都跑不出来的地方……

SFT 通常仍使用 next-token cross-entropy，但数据格式、loss mask 和训练目的不同：常见做法只对「回答」部分算分。
可以把它理解成在示范数据上继续做语言建模，不必说成和预训练完全一样。

监督信号人写的正确答案
数据量几千 ~ 几十万条
时间几小时 ~ 几天，几张卡
产物Instruct 模型：
会听话的助手
这一格里的各种方法
全参微调 Full FT

所有权重都改。效果上限最高，显存最贵（约等于重训一遍）。

PEFT：LoRA / QLoRA

冻结原模型，只训练额外的小矩阵，常见可训练参数占 0.1%~1%。QLoRA 进一步把底模量化到 4bit，再训练 LoRA。Adapter / Prefix-tuning / Prompt-tuning / (IA)³ 也属于 PEFT。

知识蒸馏 Distillation

用强模型生成训练答案，让小模型学习这些输出。只使用生成文本通常称为黑盒蒸馏；同时使用老师的概率分布称为白盒蒸馏，后者需要访问老师的内部输出。

模型生成训练数据

让模型生成候选答案，筛掉不合格的样本，再用保留下来的数据做 SFT。拒绝采样微调（RFT / RAFT）、STaR、Self-Instruct 都使用了类似流程。

安全微调

专门喂「该拒绝的问题 + 得体的拒绝方式」。红队攻出来的漏洞，会变成下一轮的训练数据。

③ 偏好对齐 PREFERENCE ALIGNMENT / RLHF · 只有好坏，没有标准答案

当任务没有唯一标准答案时，可以通过回答之间的偏好比较来训练。
训练数据长这样 —— 不是答案，是一次投票
回答 A
根据相关规定，此问题涉及多个层面，建议您咨询专业人士……
回答 B　👉 人选了这个
可以。你需要做三件事：1) …… 2) …… 3) ……

两个回答都可能没有明确的事实错误，但 B 更符合标注者对有用性的判断。偏好比较可以训练简洁、有用、少编造和在适当情况下拒绝等行为。

监督信号A 比 B 好（一次比较）
数据量几万 ~ 上百万对
时间几天，中等算力
产物更符合偏好、
边界更明确的模型
同一个目标，三条技术路线
路线一：RLHFRM ＋ PPO

先用偏好数据训练奖励模型 RM，再用强化学习提高策略模型获得的奖励。训练时通常需要维护 policy、reference、reward 和 value 等模型角色，也要防止 reward hacking。

路线二：DPO 家族免显式奖励模型

不单独训练奖励模型，直接优化 chosen、rejected 与参考模型之间的 log-prob 关系。训练流程接近监督学习，是常见的离线偏好优化方法。同族包括 IPO、KTO、ORPO 和 SimPO。

路线三：AI 反馈RLAIF / 宪法 AI

先写出一组原则，再让另一个模型依据这些原则比较回答。人工主要负责制定和检查规则，不必逐条完成全部偏好标注。

奖励模型训练

奖励模型本身也要训练，目标是让偏好答案得到更高分。奖励模型的误差会继续影响后面的强化学习。

④ 推理强化学习 RLVR · 奖励能被机器验证

数学题和代码结果可以自动验证，因此能用验证结果直接构造奖励。
这是一个循环，不是一份数据集
STEP 1
出题

一道有标准答案的数学题 / 一个带单元测试的编程任务。

STEP 2
试很多次

同一道题让模型自己写 8~64 种解法。

STEP 3
机器判分

答案对不对？测试过不过？不需要人。

STEP 4
加强对的

让「做对的那些写法」以后更容易被写出来。

↻ 反复训练后，能获得更高奖励的解题策略会更常出现，其中可能包括展开步骤、检查答案和修改错误。

人的参与只出题给答案，
不评过程
算力很贵：每题要生成几十遍
产物推理模型（o 系 / R1 类）：
肯花时间想
这一格里的各种方法
结果奖励 ORM

只根据最终答案是否正确给奖励，不评价中间步骤。实现简单，也减少了过程标注的需求。

过程奖励 PRM

对中间步骤分别打分，信号更密，但需要判断每一步是否正确，标注和验证成本更高。

算法：PPO / GRPO / RLOO

这些算法负责把奖励转成权重更新。GRPO 会对同一题采样一组答案，以组内相对得分计算优势，因此不需要额外的价值网络。DeepSeek-R1 使用了 GRPO。

Agentic RL

把奖励放在多轮、带工具的任务上，例如资料是否查对、脚本是否跑通、bug 是否修复。奖励来自环境中的执行结果。

自我改进 / 自我对弈

模型生成题目和解答，再筛选成功轨迹作为后续训练数据。这类方法试图减少对人工数据的依赖。

推理蒸馏

让大模型生成带推理步骤的答案，再用这些答案训练小模型。训练形式通常仍属于 SFT。

三 · 偏好对齐 人（或 AI）只说哪个更好
RLHF奖励模型 RM ＋ PPO

先训练奖励模型，再用强化学习优化策略模型。

奖励模型训练Reward modeling

把「人的口味」压进一个打分模型里。RLHF 的前置步骤。

DPODirect Preference Optimization

跳过显式奖励模型，直接优化偏好对。常用于离线对齐。

IPO / KTO / ORPO / SimPODPO 家族

各自的变体：KTO 不用成对标注，ORPO 把 SFT 和对齐合成一步。

写一份原则清单，让 AI 按清单评判 AI。人只写规则。

四 · 强化学习（奖励可验证） 机器判对错
RLVR可验证奖励 RL

数学答案、单元测试、编译通过 —— 奖励不来自人。

GRPO / PPO / RLOO / REINFORCE++

把奖励变成权重更新的具体算法。GRPO 省掉 critic，是常见选择之一。

结果奖励 ORM vs 过程奖励 PRM

只看结果，还是每步都评。前者稳，后者快但贵。

Agentic RL工具 / 多轮 / 环境

奖励来自实际执行结果，例如脚本是否跑通、bug 是否修复。

自我对弈 / 自我改进Self-play, self-improve

模型生成任务和解答，再把成功轨迹用于后续训练。

五 · 模型手术 不属于前四段的额外操作
模型合并Model merging / soup

对多个模型做平均、插值或其他合并。通常不用梯度，但效果可能提升，也可能互相干扰。

这些常被叫做「训练」，其实不是

判据只有一个：权重有没有被改？ 没改，就不是训练 —— 关掉窗口它就忘了。

✕写提示词 / Prompt

只是把话说清楚。改的是输入，不是模型。

✕给几个例子（few-shot）

「上下文学习」里的"学习"是个比喻。它在当场模仿，不是在变聪明。

✕RAG / 知识库

查资料再回答。公司内部材料经常更新、还要能追溯来源时，通常先考虑这个。

✕接工具 / 记忆 / 多智能体

都是模型外面的系统工程。模型本身一个字都没改。

✓Prompt-tuning

容易混淆的例外：它训练的是一段「假词向量」。有梯度，算训练。

✓Best-of-N / 多数投票

推理时多生成几遍挑最好的 —— 不算训练，但同样的机制放进训练循环里，就是第四段的 RL。

三句话，够用了

1 · 预训练提供大部分通用能力。后训练主要调整行为和任务能力，也可以写入有限的新事实。

2 · 「谁提供训练信号」是第一问。还要看目标函数、数据是否在线生成，以及哪些 token 参与 loss。

3 · 先问这事要不要训练。通常按 提示词 → RAG → LoRA / SFT → 继续预训练 → 从头训练 的成本顺序评估。
