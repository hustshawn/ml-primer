① 预训练 PRE-TRAINING · 自监督

把整个互联网遮住最后一个字，让模型猜。猜错了就改自己。重复十万亿次。
训练数据长这样 —— 就是普通文本，没有任何标注

监督信号文本自己
人的参与只筛数据，不标答案
时间几周 ~ 几个月，几万张卡
产物Base 模型：会续写，
不会听话
这一格里的各种方法
因果语言建模 CLM

猜下一个字。今天所有生成式模型（GPT / Llama / Claude / DeepSeek）都是这个。

掩码语言建模 MLM

做完形填空（BERT 那一派）。擅长理解、不擅长生成，现在基本只用于向量／检索模型。

继续预训练 CPT / DAPT

拿别人训好的 Base 模型，再喂一大堆你的领域语料（医疗、法律、代码、中文）。这是唯一能真正「灌新知识」的训练方式，也是普通团队够得着的最重训练。

中期训练 / 退火 Annealing

预训练快结束时换菜：削掉低质网页，加大教科书、数学、代码比例，同时把学习率降下来。便宜、见效快，是近两年模型能力跃升的隐形功臣。

长上下文扩展

用少量长文档接着训，把位置编码「拉长」，让 8K 变 128K / 1M。属于预训练尾巴上的一道工序。

② 监督微调 SFT / INSTRUCTION TUNING · 有标准答案

给它看几万篇「标准范文」，让它学会：人一提问，就该好好回答。
训练数据长这样 —— 成对出现，答案是人写的
输入（人问）
用三句话解释黑洞。
目标输出（人写的范文）
黑洞是引力大到光都跑不出来的地方……

和预训练数学上完全一样（还是猜下一个字），只是数据换成了对话，而且只对「回答」部分算分。
所以 SFT ≠ 新技术，SFT = 换了数据的预训练。

监督信号人写的正确答案
数据量几千 ~ 几十万条
时间几小时 ~ 几天，几张卡
产物Instruct 模型：
会听话的助手
这一格里的各种方法
全参微调 Full FT

所有权重都改。效果上限最高，显存最贵（约等于重训一遍）。

PEFT：LoRA / QLoRA

冻住原模型，只外挂一小片可训练的补丁（常见只有 0.1%~1% 的参数）。显存降一个量级，效果多数场景够用。QLoRA = 把底模压成 4bit 再挂 LoRA，单卡就能微调很大的模型。
同类还有 Adapter / Prefix-tuning / Prompt-tuning / (IA)³ —— 思路都是「别动主体，加个小旋钮」。

知识蒸馏 Distillation

让强模型当老师出题又给答案，小模型照抄。今天绝大多数开源小模型的对话能力都来自这一步。
抄文字叫黑盒蒸馏；连老师的概率分布一起抄叫白盒蒸馏（效果更好，但要能拿到老师的内部输出）。

自造数据自己学

范文太贵，就让模型自己写一堆答案，只留下对的那些，再拿去 SFT。
拒绝采样微调（RFT / RAFT）、STaR、Self-Instruct 都是这一套。它是 SFT 和 RL 之间的过渡形态。

安全微调

专门喂「该拒绝的问题 + 得体的拒绝方式」。红队攻出来的漏洞，会变成下一轮的训练数据。

③ 偏好对齐 PREFERENCE ALIGNMENT / RLHF · 只有好坏，没有标准答案

「什么是好回答」写不成范文，但人一眼能挑出来。那就让它学人的口味。
训练数据长这样 —— 不是答案，是一次投票
回答 A
根据相关规定，此问题涉及多个层面，建议您咨询专业人士……
回答 B　👉 人选了这个
可以。你需要做三件事：1) …… 2) …… 3) ……

两个都不算错。B 只是更有用。这种「说不清但感觉得到」的标准，只能靠比较来教。
它治的是 SFT 治不了的病：啰嗦、和稀泥、瞎编、该拒绝时不拒绝。

监督信号A 比 B 好（一次比较）
数据量几万 ~ 上百万对
时间几天，中等算力
产物「有人味」的模型：
能用、听得懂、有边界
同一个目标，三条技术路线
路线一：RLHFRM ＋ PPO

先用人的投票训一个「打分器」（奖励模型 RM），再用强化学习让模型去讨好这个打分器。ChatGPT 就是靠这条路出圈的。
效果强，但要同时伺候四个模型、调参痛苦、还会「钻打分器的空子」（reward hacking）。

路线二：DPO 一家免打分器

数学上证明：不用训打分器，直接让「被选中的答案」概率升高、「被淘汰的」降低就行。一行 loss，训练像 SFT 一样简单，成了开源界默认选择。
同族：IPO、KTO（只需标「这条好/不好」，不用成对）、ORPO（SFT 和对齐一步做完）、SimPO。

路线三：AI 来投票RLAIF / 宪法 AI

人工投票太慢太贵，那就写一份原则清单（"宪法"），让 AI 按清单去评判 AI。人只负责写规则，不再逐条打分。可扩展性大幅提升，也是「AI 反馈」这一支的起点。

顺带一提

训那个奖励模型本身也是一次训练（目标是「给好答案打高分」）。它训不好，后面全白干。

④ 推理强化学习 RLVR · 奖励能被机器验证

数学题和代码有一个好处：对错不用问人。那就让模型自己刷题，刷对了就加强。
这是一个循环，不是一份数据集
STEP 1
出题

一道有标准答案的数学题 / 一个带单元测试的编程任务。

STEP 2
试很多次

同一道题让模型自己写 8~64 种解法。

STEP 3
机器判分

答案对不对？测试过不过？不需要人。

STEP 4
加强对的

让「做对的那些写法」以后更容易被写出来。

↻ 转几万圈之后，模型自己学会了：先慢慢想、多检查、发现不对就回头 ——「长思维链」是被奖励逼出来的，没人教过它
监督信号可自动验证的对错
人的参与只出题给答案，
不评过程
算力很贵：每题要生成几十遍
产物推理模型（o 系 / R1 类）：
肯花时间想
这一格里的各种方法
结果奖励 ORM

只看最终答案对不对，中间怎么绕的不管。简单、不易被钻空子，是目前主流。

过程奖励 PRM

每一步都打分。信号密集、学得快，但要标「每一步对不对」，贵，而且容易被钻空子。

算法：PPO / GRPO / RLOO

都是「怎么把奖励变成权重更新」的具体做法。GRPO 的思路很直观：同一题采样一组答案，比组内平均分高的就鼓励，低的就抑制，因此省掉了额外的价值网络 —— 便宜，DeepSeek-R1 用它出名。

Agentic RL

把奖励挂在多轮、带工具的任务上：能不能查对资料、跑通脚本、改完这个 bug。奖励来自真实环境的执行结果。这是当下最热的前沿。

自我改进 / 自我对弈

模型自己出题、自己解、自己筛，把成功轨迹回灌成训练数据，滚雪球。摆脱人工数据上限的方向。

推理蒸馏

让大推理模型把「想的过程」完整写出来，小模型照抄这个思考过程。这就是那些「7B 也会做数学」的小模型的来历 —— 严格说它落在 SFT 格里。

三 · 偏好对齐 人（或 AI）只说哪个更好
RLHF奖励模型 RM ＋ PPO

先训打分器，再用 RL 去讨好它。ChatGPT 的成名路线。

奖励模型训练Reward modeling

把「人的口味」压进一个打分模型里。RLHF 的前置步骤。

DPODirect Preference Optimization

跳过打分器，直接优化偏好。开源界默认选择。

IPO / KTO / ORPO / SimPODPO 家族

各自的变体：KTO 不用成对标注，ORPO 把 SFT 和对齐合成一步。

RLAIF · 宪法 AIConstitutional AI

写一份原则清单，让 AI 按清单评判 AI。人只写规则。

四 · 强化学习（奖励可验证） 机器判对错
RLVR可验证奖励 RL

数学答案、单元测试、编译通过 —— 奖励不来自人。

GRPO / PPO / RLOO / REINFORCE++

把奖励变成权重更新的具体算法。GRPO 最省，因此最流行。

结果奖励 ORM vs 过程奖励 PRM

只看结果，还是每步都评。前者稳，后者快但贵。

Agentic RL工具 / 多轮 / 环境

奖励来自真实执行：脚本跑通了吗？bug 修好了吗？当下最热。

自我对弈 / 自我改进Self-play, self-improve

自己出题自己解，成功轨迹回灌。突破人工数据上限。

五 · 模型手术 不学新东西，只改形态（常被误当成「训练」）

遗忘Unlearning

定向让模型忘掉某些内容（版权、隐私）。

这些常被叫做「训练」，其实不是

判据只有一个：权重有没有被改？ 没改，就不是训练 —— 关掉窗口它就忘了。

✕写提示词 / Prompt

只是把话说清楚。改的是输入，不是模型。

✕给几个例子（few-shot）

「上下文学习」里的"学习"是个比喻。它在当场模仿，不是在变聪明。

✕RAG / 知识库

查资料再回答。要让模型「知道公司内部的事」，这个几乎总是比微调更对。

✕接工具 / 记忆 / 多智能体

都是模型外面的系统工程。模型本身一个字都没改。

✓Prompt-tuning

容易混淆的例外：它训练的是一段「假词向量」。有梯度，算训练。

✓Best-of-N / 多数投票

推理时多生成几遍挑最好的 —— 不算训练，但同样的机制放进训练循环里，就是第四段的 RL。

三句话，够用了

1 · 知识在第一段学完。后面三段不加知识，只教它怎么把知识用出来。

2 · 分辨任何一种训练方式，只问「谁在打分」。没人打分＝预训练；人写答案＝SFT；人挑好坏＝对齐；机器判对错＝RL。

3 · 先问这事要不要训练。顺序是 提示词 → RAG → LoRA → 继续预训练 → 从头训。
八成的「我要微调」，停在前两步就解决了。
