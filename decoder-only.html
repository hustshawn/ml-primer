Decoder-only

为什么现在的 LLM
清一色是 decoder-only

2018 年还有三条路在跑。到现在，你能叫得出名字的生成式大模型基本只剩一种架构。
不是审美收敛 —— 是一堆约束把路收窄了。而所有约束都能追到同一张图上。

五个理由 · 先看结论
  1. 每个 token 都是一道题。 同一段文本，因果 mask 能出 7 道题，双向只能出 1 道 —— 同样的算力，训练信号差 6 倍多。
  2. 所有任务都能写成「接着写」。 翻译、分类、摘要、多轮对话，全塌进同一个格式，不用给每个任务定「哪一半是输入」。
  3. 算过的永远不用再算。 因果 mask 保证前面的 token 不会因为后面来了新词而改变 —— 这就是 KV cache 成立的唯一前提。
  4. 一种零件，堆 N 层。 没有 cross-attention、没有 encoder/decoder 参数分配问题。越简单的东西越好往上堆、越好切到几千张卡上。
  5. 网上的数据本来就是一条流。 不是 (输入, 输出) 对。「猜下一个词」直接吃原始语料，零加工。

名字很误导，先纠正一下 「decoder-only」不是「只有解码器」。原论文的 decoder 块有三个子层：因果自注意力 + cross-attention（看 encoder 的输出）+ FFN。而 decoder-only 模型把 cross-attention 删了 —— 剩下的两个子层（自注意力 + FFN）跟 encoder 块结构完全一样。

所以 encoder-only 和 decoder-only 的真实差别，只剩一件事：自注意力那一步允不允许往后看。整个架构之争，就是一张 mask 之争。

为什么双向就只能涂掉一部分 因为双向看得见答案。你问它「下一个词是什么」，它往右一瞄就抄到了 —— 这道题不产生任何学习。想出题，必须先把答案涂掉，而涂掉的地方就没法当上下文用了。这就是 BERT 只涂 15% 的原因：涂太多，剩下的上下文不够；涂太少，一次前向就没几道题。这个两难，因果 mask 根本不存在。

公平起见 完形填空的每道题质量更高 —— 它能同时用上左右两边的上下文，比只能往前看信息更足。这是真的优势。

但 6.6 倍不是「每题更好」能补回来的。当你要烧的是几万张卡、几万亿 token，「同样一遍前向能不能榨出 6 倍的题」就成了压倒性的因素。规模越大，这一条越致命。

04理由二 · 所有任务都能写成「接着写」

encoder-decoder 要求你先回答一个问题：哪一半是输入，哪一半是输出？decoder-only 不问 —— 全部拼成一条流，让它接着写。选一个任务看看差别。

Decoder-only · 一条流
墙没了。灰色是喂进去的，橙色是它自己往下写的 —— 而模型内部完全不区分这两段，它只是在一直「猜下一个」。
这条解锁了一件更大的事 既然任务只是「换一段前文」，那换任务就不用动参数了 —— 直接在 prompt 里写清要求、塞几个例子。这就是 in-context learning / few-shot prompting，GPT-3（2020，175B 参数）把它变成了主流用法。

而 encoder-decoder 的那道墙在多轮对话里根本划不出来：第 3 轮的时候，前两轮的「模型输出」到底算输入还是输出？decoder-only 不用回答这个问题 —— 全是同一条流上的 token。

05理由三 · 算过的永远不用再算

因果 mask 有一个白送的性质：第 i 个 token 的表示，永远不会受到 i 之后任何东西的影响。所以它算一次就永久有效，可以存起来 —— 这就是 KV cache。双向没有这个性质：来了新词，前面所有表示全变，只能全部重算。

诚实一点：这条不是打 encoder-decoder 的 encoder-decoder 的 decoder 也是因果的，它照样能用 KV cache，cross-attention 的 K/V 也能缓存。这条真正打死的是「让 prompt 部分双向可见」这个念头（encoder-only，以及 prefix-LM 的前缀那一段）。

decoder-only 额外多赚的是 prefix 复用：system prompt、前几轮对话，因为跟生成部分在同一条因果流里，可以整段缓存下来，下一轮直接往后接。encoder-decoder 那边输入一改，双向的 encoder 就得整个重跑。

07理由五 · 网上的数据本来就是一条流

这里有几个新旋钮 「涂 15%」「平均长度 3」「用什么哨兵符号」—— 这些都是人拍出来的超参，是为了把一条流硬掰成「输入 / 输出」而发明的。它们全都可能拍错，而且都得靠实验去调。

「猜下一个词」一个这样的旋钮都没有。它不是一个更聪明的目标函数，它是一个不需要发明的目标函数。

08白送的礼物 · mask 自己就带着位置信息

这条不是设计目标，是撞出来的副作用，但它很能说明因果结构有多「自然」。

因果：能数出自己是第几个

Decoder-only

第 1 个 token 只能看见 1 个东西，第 5 个能看见 5 个。「我能看见几个」= 「我前面有几个」= 我的绝对位置。位置信息从 mask 的形状里免费漏出来了。

双向：每个位置看到的都一样多

Encoder-only

全都看见全部 8 个。没有任何可数的锚点 —— 位置信息必须从外面显式喂进去，否则这个模型眼里的句子就是一个词袋。

有实验支撑 Haviv 等（2022）《Transformer Language Models without Positional Encodings Still Learn Positional Information》发现：因果语言模型完全不加位置编码也能训得不错，探针能在网络内部读出「绝对位置」的表示。作者的解释正是——因果注意力让每个 token 能推断出自己前面有多少个前驱，从而近似出自己的绝对位置。

注意：这不代表实际模型不用位置编码（现在都用 RoPE 之类）。它只说明因果 mask 本身就在做一部分位置编码的活。

09说点不那么爽的

「decoder-only 更强」这句话，收窄到能站住脚的版本是：在「预训练到极大、然后靠 prompt 使用」这条路线上，它更强。换掉路线，结论就会翻。

同规模对照实验

换成「多任务微调」，赢的就不是它了

Wang 等（ICML 2022）做过一次干净的对照：三种架构 × 两种预训练目标，模型超过 50 亿参数、训了超过 1700 亿 token。结论是分岔的 ——

纯无监督预训练之后比 zero-shot：因果 decoder-only + 自回归目标最强（跟现实一致）。
但加上多任务微调之后：非因果可见性 + 掩码语言建模的组合反而最好。

所以 decoder-only 赢的不是「架构本身绝对更优」这场比赛，而是「谁最适合被无监督地喂到极大、然后靠 prompt 驱动」这场比赛。恰好这场比赛才是过去几年真正在跑的那场。

arXiv:2204.05832

Encoder-only 没死

它只是不再叫「LLM」了

向量检索的 embedding 模型、重排序器、各种文本分类和内容审核 —— BERT 系的双向编码器在这些地方仍是主力，因为这些任务要的就是「读懂整句」，不需要往下写，双向看两边的优势可以完整吃到。

「现在的 LLM 都是 decoder-only」这句话，主语其实是生成式 LLM。

Encoder-decoder 也没死

输入和输出是「两种东西」的时候，它依然合理

语音转文字（Whisper 就是 encoder-decoder：encoder 吃音频，decoder 写文字）、专用机器翻译、以及不少多模态模型用 cross-attention 把图像/音频注入语言模型 —— 这些场景里输入根本不是同一条 token 流，那道「墙」不是负担，是结构上本来就该有的东西。

混合体存在过

prefix-LM 不是输在效果，是输在复杂度

UL2、GLM 这类做法把前缀设为双向可见、后半段保持因果，想把两边的好处都拿到，效果也确实不差。但它多了一个「前缀边界在哪」的问题、多了一种 mask 形状、KV cache 和各种推理优化都要额外照顾。

而对面是一个只有一种块、只有一种 mask、全世界的 kernel 都为它写好了的方案。这不是一场公平的比较 —— 但工程上的胜负就是这么定的。

如果只记一句

decoder-only 赢的不是「更聪明」，
是「更省、更简单、更好堆」。

往后看一眼就能作弊 → 所以必须涂掉答案 → 所以一遍前向只出得了 15% 的题 → 所以省不下算力；而且前面的表示会被后面改写 → 所以存不住缓存。

因果 mask 一刀切掉「往后看」，上面这一串问题全部消失。代价是每道题的上下文少了一半 —— 在足够大的规模面前，这个代价便宜得离谱。

一张下三角形的 mask，撑起了现在几乎所有的生成式大模型。
