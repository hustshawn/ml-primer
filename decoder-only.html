Decoder-only

为什么主流生成式 LLM
大多是 decoder-only

2018 年还有三类架构在竞争。现在，主流生成式大模型基本都采用 decoder-only。
原因可以从训练信号、缓存、扩展方式和数据形态几方面解释，而这些差别都与 attention mask 有关。

下面用这三种 mask 解释因果架构为什么成为生成式大模型的主流。

五个理由 · 先看结论
  1. 大多数位置都能产生 loss。 因果语言建模可以在几乎每个位置预测下一个 token；MLM 只在被遮住的位置算 loss。前者监督更密，但不能直接换算成「强几倍」。
  2. 所有任务都能写成「接着写」。 翻译、分类、摘要、多轮对话可以统一成同一种格式，不用给每个任务单独划分输入和输出。
  3. 已经计算的表示可以复用。 因果 mask 保证前面的 token 不会因为后面来了新词而改变，这是 KV cache 成立的前提。
  4. 一种零件，堆 N 层。 没有 cross-attention、没有 encoder/decoder 参数分配问题。越简单的东西越好往上堆、越好切到几千张卡上。
  5. 网上的数据本来就是一条流。 网页、书和代码通常是连续文本，不需要先整理成 (输入, 输出) 对。

名字很误导，先纠正一下 「decoder-only」不是「只有解码器」。原论文的 decoder 块有三个子层：因果自注意力 + cross-attention（看 encoder 的输出）+ FFN。而 decoder-only 模型把 cross-attention 删了 —— 剩下的两个子层（自注意力 + FFN）跟 encoder 块结构完全一样。

encoder-only 和 decoder-only 的主要结构差别，是自注意力能否看到后续 token。这个差别由 attention mask 决定。

这也支持 in-context learning 既然任务只是「换一段前文」，那换任务就不用动参数了 —— 直接在 prompt 里写清要求、塞几个例子。这就是 in-context learning / few-shot prompting，GPT-3（2020，175B 参数）把它变成了主流用法。

多轮对话也很难长期固定输入和输出的边界：到第 3 轮时，前两轮的模型输出已经成为新一轮输入。decoder-only 直接把整段历史当作同一条 token 流。

05理由三 · 已计算的表示可以复用

适用范围 encoder-decoder 的 decoder 也是因果的，同样能用 KV cache，cross-attention 的 K/V 也能缓存。这里受影响的是让 prompt 部分双向可见的结构，例如 encoder-only 和 prefix-LM 的前缀部分。

08因果 mask 带来的位置信号

这不是最初的设计目标，但实验表明，因果可见性本身会提供一部分位置信息。

因果：能数出自己是第几个

Decoder-only

第 1 个 token 只能看见 1 个东西，第 5 个能看见 5 个。「我能看见几个」= 「我前面有几个」= 我的绝对位置。位置信息从 mask 的形状里免费漏出来了。

双向：每个位置看到的都一样多

Encoder-only

全都看见全部 8 个。没有任何可数的锚点 —— 位置信息必须从外面显式喂进去，否则这个模型眼里的句子就是一个词袋。

有实验支撑 Haviv 等（2022）《Transformer Language Models without Positional Encodings Still Learn Positional Information》发现：因果语言模型完全不加位置编码也能训得不错，探针能在网络内部读出「绝对位置」的表示。作者的解释正是——因果注意力让每个 token 能推断出自己前面有多少个前驱，从而近似出自己的绝对位置。

注意：这不代表实际模型不用位置编码（现在都用 RoPE 之类）。它只说明因果 mask 本身就在做一部分位置编码的活。

09结论的适用范围

decoder-only 的优势主要出现在大规模预训练后通过 prompt 使用这条路线。训练方式和任务形态改变后，结果也可能改变。

同规模对照实验

多任务微调下，结果会改变

Wang 等（ICML 2022）做过一次干净的对照：三种架构 × 两种预训练目标，模型超过 50 亿参数、训了超过 1700 亿 token。结论是分岔的 ——

纯无监督预训练之后比 zero-shot：因果 decoder-only + 自回归目标最强（跟现实一致）。
但加上多任务微调之后：非因果可见性 + 掩码语言建模的组合反而最好。

这说明 decoder-only 更适合大规模无监督预训练后通过 prompt 使用；它并不在所有训练设置下都占优。过去几年，主流生成式模型主要采用的正是前一种路线。

arXiv:2204.05832

Encoder-only 没死

它仍然广泛用于非生成任务

向量检索的 embedding 模型、重排序器、各种文本分类和内容审核 —— BERT 系的双向编码器在这些地方仍是主力，因为这些任务要的就是「读懂整句」，不需要往下写，双向看两边的优势可以完整吃到。

「现在的 LLM 都是 decoder-only」这句话，主语其实是生成式 LLM。

Encoder-decoder 也没死

输入和输出是「两种东西」的时候，它依然合理

语音转文字（Whisper 就是 encoder-decoder：encoder 吃音频，decoder 写文字）、专用机器翻译、以及不少多模态模型用 cross-attention 把图像/音频注入语言模型 —— 这些场景里输入根本不是同一条 token 流，那道「墙」不是负担，是结构上本来就该有的东西。

混合体存在过

prefix-LM 的工程复杂度更高

UL2、GLM 这类做法把前缀设为双向可见、后半段保持因果，想把两边的好处都拿到，效果也确实不差。但它多了一个「前缀边界在哪」的问题、多了一种 mask 形状、KV cache 和各种推理优化都要额外照顾。

纯因果 decoder 只有一种块和一种 mask，现有 kernel 也普遍优先支持它。长期积累的工程支持进一步扩大了两者的部署成本差距。

核心结论

decoder-only 更适合大规模生成模型，
因为它训练信号密、结构规则、缓存简单。

允许往后看时，需要遮住一部分答案才能构造训练目标，一次前向产生 loss 的位置也会减少；同时，新 token 会改变前面位置的表示，缓存更难复用。

因果 mask 禁止访问未来 token，避开了这些问题。代价是每个训练位置只能使用左侧上下文，而大规模训练通常愿意接受这个取舍。

因果 mask 决定了 decoder-only 的训练方式、缓存能力和扩展路径。
