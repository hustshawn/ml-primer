Post-training · 后训练

预训练之后那一堆方法，看谁打分，答案哪来

SFT、RLHF、PPO、DPO、拒绝采样、GRPO、蒸馏 —— 名字一大把，目的都很接近：把模型已经会的东西，往人想要的方向拧。要看懂它们的区别，先看两件事：谁判断答案好不好，训练用的答案从哪里来。

01 · 起点

预训练模型首先学会续写，
而不是稳定地按要求回答

预训练的核心任务只有一个：给一段文字，猜下一个 token。所以刚出炉的 base 模型看到一个问题时，可能直接回答，也可能把它当成文章、试卷或论坛帖子的一部分继续往下写。

base 模型

你：法国的首都是哪里？

它：德国的首都是哪里？
意大利的首都是哪里？
西班牙的首都是哪里？
（参考答案见第 42 页）

它很可能已经学到「法国首都是巴黎」。问题在于，它还没稳定学会看到问句就直接回答，于是把这句话续成了一份练习题。

post-training 之后

你：法国的首都是哪里？

它：巴黎。

在这个例子里，变化的不是「巴黎」这条知识，而是行为：看到问句要答、答完要停、不确定要说不确定、遇到不该做的请求要拒绝。

Post-training 的主要任务不是灌入大量知识，而是调整「在无数种合理续写里挑哪一种」。

严格说，SFT 也能让模型记住一些新信息。但用它维护大量、经常变化的知识通常很低效，还可能影响原有能力。想让模型使用公司内部文档，通常更适合接检索；后训练主要负责调整行为。

03 · 第一种 人写的示范

SFT：还是预测下一个 token，
通常只让回答部分计算 loss

监督微调（supervised fine-tuning）的核心计算和预训练相同：预测下一个 token，使用交叉熵。典型的指令微调主要改了两件事。

改动一

数据换成对话

从「网上的文章」换成「一个请求 + 一个人想要的回答」，中间用固定的特殊 token 隔开。所谓 chat template 就是在这一步教进去的 —— 模型不是天生认识 <|assistant|>，是这一步反复见到才学会「看到这个符号，该我说话了」。

改动二

只让回答部分计入 loss

用户的问题仍然会被模型读到，但只作为上下文；训练目标主要落在助手回答上。这样可以让模型把能力集中在「看到这个请求后应该怎么答」，而不是同时模仿用户怎么提问。

实验台loss 算在哪些 token 上

这一步主要教的是格式和行为，因此所需数据可以比预训练少很多。InstructGPT 的 SFT 集大约有 1.3 万条人写示范；后来 LIMA 用 1000 条精挑的示范，也展示了高质量小数据的效果。

实际流水线通常先做 SFT：模型先学会按格式回答，后面那些「让它自己生成再打分」的方法才更容易采到可用的答案。它不是理论上必需，但通常能让后续训练稳定很多。

04 · 为什么不能就停在这

SFT 的三个天花板

① 判断好坏，通常比亲自示范容易

让你写一首更好的诗很难，让你在两首里挑一首往往容易得多。只靠示范数据时，答案质量会明显受示范作者能力限制。

② 不擅长直接表达「A 比 B 好」

SFT 可以用正确示范间接教模型「不要编参考文献」，但很难直接利用「这个答案比另一个差在哪里」的信息。偏好比较更适合表达这种相对好坏。

③ 训练时看到的前文太理想

训练时，要预测的 token 前面通常是标准答案；真正生成时，前面却是模型自己刚写的内容，可能已经有一点偏。它较少练习如何从自己的小错误里往回收。

这些限制引出了两条常见思路：让人比较答案，而不必完整写答案；让模型从自己真正可能生成的回答中学习。

05 · 零件 人的偏好

奖励模型：
把「更好」压成一个数

要让人打分，得先解决一个问题：人不可能在训练循环里打几百万次分。因此可以先训练另一个模型去模仿人的偏好，再让它批量打分 —— 这就是奖励模型（reward model, RM）。

数据：同一个问题采两个回答，人只回答一句「哪个更好」。
模型：通常从 SFT 模型开始，把最后的输出层改成只输出一个数。这个数用来表示模型对「这个回答有多好」的判断。

loss = − log σ( r(好答案) − r(坏答案) ) // σ 是 sigmoid，把任意实数压到 0~1

注意这个式子里只有差值。给全世界所有答案的分数一起 +5，loss 一个小数点都不变。

σ(Δ)：模型认为
「好的确实更好」的概率
loss

RM 的用处，是把有限的人工比较变成一个可以反复调用的自动打分器。人只标一批偏好对，训练阶段就可以让 RM 大规模地替人排序。

代价也在这里：RM 是个代理，不是真的人。它通常在接近训练数据的范围内更可靠；模型一旦跑到 RM 不熟悉的地方，分数就可能失真。很多「reward hacking / 刷分」问题都与此有关。

06 · 第二种 人的偏好 · 在线

RLHF：自己生成，
按分数推，用 KL 拴住

有了会打分的 RM，循环就转起来了。一个 step 里四件事：

① 采

拿一个 prompt，让当前模型自己写一个回答。

② 评

RM 给这个回答一个分。

③ 拴

用 KL 衡量它和训练前那个模型差多远，再从奖励里扣掉一部分。

④ 推

按「分 − 罚」的方向改参数：让这次这么写的概率变高。

贵在哪？典型的 PPO-RLHF 训练要同时维护四种模型角色：

  • policy —— 正在被训的那个，有梯度、有优化器状态
  • reference —— SFT 模型的冻结副本，只用来算「跑多远了」
  • reward model —— 冻结，只打分
  • critic / value —— 也在训，先估一个「大概能拿多少分」的基准，减少训练时的随机波动

再加上每个 step 中间都要做一次完整的自回归生成，一个 token 一个 token 地吐答案。RLHF 的主要难点因此不是 loss 本身，而是工程重、资源贵、超参敏感。

③ 那个「拴」是整套方案的保险丝

KL 可以理解成「当前模型和参考模型的输出分布差了多少」。如果只让模型追 RM 给的分数，它可能找到 RM 的漏洞并一直薅。KL 罚项是在提醒它：可以变好，但别一下跑得离原模型太远。

实验台KL 拴绳松紧示意，非实测数字
RM 给的分
离原模型多远
真人看了觉得
这时候它会这样回答「文件权限该设成多少」

成绩是实打实的：InstructGPT 论文里，一个 1.3B 的 RLHF 模型的输出，被标注员判为优于 175B 的原始 GPT-3。参数量差一百多倍，赢的不是知识，是「按要求做事」。

PPO 只是第 ④ 步「怎么推参数」的具体算法（核心是一个 clip，防止一步走太远）。把它换成别的 RL 算法，上面这一圈的形状不变 —— 所以别把 PPO 和 RLHF 当同一个词。

07 · 第三种 人的偏好 · 离线

DPO：把奖励模型和采样
一起删掉

看着上面那一圈，很自然会问一句：人给的本来就是「A 比 B 好」，我们却先把它压成一个 RM，再让 RM 去教模型。中间这一道能不能跳过？

DPO（2023）的答案是能。它不再单独训练一个 RM，而是直接拿「好答案、坏答案」这一对来调整模型：相对于参考模型，让当前模型更偏向好答案，而不是坏答案。

推导之后，这个目标可以写成下面的 loss。训练时只需要读取固定的偏好数据，不必在每个 step 里现场生成答案：

loss = − log σ( β · [ log π(好)/πref(好) − log π(坏)/πref(坏) ] )

直觉上，它比较两件事：当前模型相对参考模型，给好答案增加了多少概率，又给坏答案增加了多少概率。前者应该比后者大。训练时需要用当前模型和参考模型分别计算好、坏答案的概率，但没有在线生成，没有 RM，也没有 critic。

省掉了
  • 训一个 RM 的那一整轮
  • 训练循环里的自回归生成
  • critic 模型
  • 一堆 RL 超参
代价
  • 固定数据不会跟模型同步变化。训着训着模型变了，偏好对仍然来自旧模型，和当前模型可能越来越不匹配。
  • 它只保证「好比坏更可能」，不保证「好本身更可能」。实测里常见：两边的概率一起往下掉，只是好的掉得慢点。

第一个代价的现实解法是迭代：训一轮 → 用新模型重新采样 → 重新标偏好 → 再训。Llama 3 就是这么干的，来回六轮。绕了一圈，又把「让模型自己生成」这件事请回来了 —— 只是搬到了循环外面。

DPO 家族：都在改同一个 loss 的形状

你听过的这几个名字，大体和 DPO 处在同一类（离线、使用偏好信号、不单独训练 RM），主要区别在 loss 的具体设计：

IPO

换掉 log-sigmoid，避免模型一味把差值往无穷大推、进而过拟合偏好数据。

KTO

不要成对数据。单条「这条行 / 这条不行」也能训 —— 现实里的反馈（点赞点踩）本来就是这个形状。

ORPO

把 SFT 和偏好合成一个 loss，连参考模型都不要，从 base 模型一步到位。

SimPO

也去掉参考模型，用「按长度归一化的平均 log 概率」当隐式 reward，顺手压一压「越长越容易赢」的毛病。

还有一个换的是第 2 问而不是式子：RLAIF / Constitutional AI —— 打分的从人换成另一个模型（给它一份写好的原则，让它挑）。训练方法本身不必改变，偏好数据则更容易大规模生成。

08 · 第四种 自己采，再当示范

拒绝采样：最直接的一条，
也是常见的工业方案

做法朴素到不像一个方法：

①

一个 prompt，让模型采 N 个回答（几个到几十个）

②

用 RM（或验证器、或人）挑出最好的那一个

③

把它当成一条新示范，做一次普通 SFT

④

用新模型再采一轮，回到 ①

训练方法仍然是 SFT，所以比较简单、稳定，也不需要 critic。不同之处在于：示范由当前模型生成，再经过筛选。这样模型学到的，是自己真正可能写出的回答中较好的那些。它因此常被用作工业后训练的主力环节；Llama 2 和 Llama 3 的后训练都大量使用了这条路线。

实验台N 开大一点，挑到的是更好的，还是更会骗分的？模拟数据
被挑中那条的 · 打分器给的分
被挑中那条的 · 真实质量
打分器分数 真实质量

一旦拿代理分数当目标去挑极值，代理和真实目标就可能逐渐分开。采样池越大，挑到「刚好骗过打分器的答案」的风险也越高。

它和 RL 的差别也在这儿：拒绝采样只学被选中的那一条，剩下 N−1 条直接扔了；RL 还会利用「每条答案比基准好或差多少」。因此 RL 能用到更多信息，但拒绝采样通常更简单、更稳定。

09 · 第五种 机器自动验证

RLVR / GRPO：
打分的换成一段能跑的代码

回到 RLHF 那一圈，只换掉一个零件：打分的从 RM 换成一个验证器。数学题可以比对最终答案，代码题可以跑单元测试，格式要求可以用规则检查。最简单的 reward 是 0 或 1，也可以使用通过率等更细的分数。

容易扩规模

题目和标准答案已经存在时，不需要逐条请人比较回答

信号更直接

通过测试通常比「RM 猜人会不会喜欢」更接近任务目标

较难靠表面功夫刷分

堆客套话不能让单元测试通过，但验证器设计不完整时仍可能被钻空子

GRPO 顺手又删掉一个模型

PPO 里的 critic 会先估一个基准，用来判断这次拿到的分数到底算高还是低。GRPO 换了一种更直接的参照：同一个 prompt 一次采一组（G 个）回答，让组内答案互相比较。高于组内平均的答案往上推，低于平均的往下压，因此不再需要单独的 critic。

优势（简化理解） = 自己这条的分 − 这一组的平均分 // 不再单独训练 critic
实验台一组 8 个回答，组内均值当参照
组内平均分 这一步学到东西了吗

这也解释了 RLVR 的数据配方核心：题的难度最好落在模型「不是全对也不是全错」的区间。如果同一组全对或全错，组内答案没有高低差别，提供不了有效的相对奖励信号。

最重要的一点：较长的「思考」可以从结果奖励中自己长出来。

当奖励主要看最终答案是否正确时，模型可能发现「先多推几步再答」更容易拿到高分，于是回答逐渐变长。DeepSeek-R1 报告里的响应长度曲线就展示了这种现象：不必逐条人工示范「要写多长」，模型也可能学会投入更多推理步骤。

限制也很硬：得有验证器。数学、代码、形式化推理有；「写一封得体的邮件」「这个回答有没有冒犯人」没有 —— 那部分还得靠人的偏好。所以今天的流水线两边都要，不是二选一。

10 · 那蒸馏算哪一种

蒸馏不是一种训练算法，
是一种数据来源

它经常和上面几种并列被提，但它不在同一层：它换的是「答案从哪来」，训练算法照旧。

黑盒 / 序列级

把强模型的输出当示范

采一批老师的回答，做一次普通 SFT。DeepSeek 放出的那批 R1-Distill-Qwen / Llama 就是这么来的：用 R1 生成的约 80 万条样本纯 SFT，没做 RL。

白盒 / logits 级

对着老师的整个分布学

老师给的不是一个 token，是每个位置上词表的完整概率分布，学生对着它做 KL。信息量大得多，但要求两边同一套 tokenizer，而且你得有老师的权重。

学生学到什么，很大程度上取决于老师展示了什么，以及蒸馏数据覆盖了什么。它能高效地把「会做事」搬过去，但能力上限通常会受老师和数据限制。这也正是验证器那条路的价值所在 —— 它的信号来自外部世界，不只来自另一个模型。

11 · 词汇表

这些词，不必靠上下文猜

这里不重复解释 token、loss 这类常用词，只收录会影响理解、但不一定人人熟悉的术语。

KL · KL 散度

衡量两个概率分布差多远。在本文里，它主要用来限制训练后的模型不要一下偏离参考模型太多。

policy · 策略模型

正在生成答案、也正在被训练的模型。RL 语境里的 policy，在这里基本就是「当前模型」。

reference model · 参考模型

训练开始前冻结的一份模型副本。它不更新，只负责告诉我们当前模型已经走了多远。

reward model · 奖励模型

模仿人类偏好给回答打分的模型。它给的是代理分数，不等于真实质量的绝对刻度。

critic / value · 价值模型

先估计「正常情况下大概能拿多少分」，给实际奖励提供一个比较基准，减少训练波动。

online / offline · 在线 / 离线

在线指训练循环里由当前模型现场生成答案；离线指先准备好固定数据，再集中训练。

verifier · 验证器

用标准答案、单元测试或规则自动检查结果的程序。它比 RM 更直接，但只会检查被明确写进规则的部分。

logits

模型为词表里每个 token 给出的原始分数；经过归一化后，才变成下一 token 的概率分布。

三条流水线的三个共同点

  • 常见顺序是先 SFT。模型先学会按格式开口，后面「自己生成再打分」更容易采到值得奖励的东西。R1-Zero 证明了纯 RL 也能长出推理能力，但输出可读性差、还会中英文混着说 —— 所以正式版仍把冷启动 SFT 加了回来。
  • 强流水线通常会迭代。采样 → 训 → 用新模型重新采样。因为模型一变，旧数据就可能越来越不匹配，定期更新数据往往能继续带来收益。
  • 偏好和验证器并存。能自动判对错的任务适合验证器；难以写成明确规则的质量标准，仍要依靠人或模型给出的偏好。

再遇到一个没听过的后训练方法，就先拿三个问题问它：一条样本长什么样、谁打分、答案从哪里来。先把位置定住，再看它具体怎么优化。
