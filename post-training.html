Post-training · 后训练

预训练之后这些方法，看谁打分，答案哪来

SFT、RLHF、PPO、DPO、拒绝采样、GRPO、蒸馏，名字很多，目的接近。它们把模型已经会的能力，调整到人想要的方向。要理解区别，先看两点：谁判断答案好坏，训练答案从哪里来。

01 · 起点

预训练模型先学会续写，
后训练再调整回答方式

预训练的核心任务只有一个：给一段文字，预测下一个 token。因此，base 模型刚完成预训练时，看到问题可能直接回答，也可能把问题当成文章、试卷或论坛帖子的一部分，继续写下去。

base 模型

用户：法国的首都是哪里？

它：德国的首都是哪里？
意大利的首都是哪里？
西班牙的首都是哪里？
（参考答案见第 42 页）

它可能已经学到「法国首都是巴黎」。问题是，它还没有稳定学会看到问句就直接回答，因此把这句话当成练习题的一部分，继续写了下去。

post-training 之后

用户：法国的首都是哪里？

它：巴黎。

在这个例子里，「巴黎」这条知识没有变化。后训练调整的是行为：看到问句要回答、回答后要停止、不确定时要说不确定、遇到不该做的请求要拒绝。

Post-training 主要调整模型会选择哪一种合理续写，也就是它的回答行为。

严格说，SFT 也能让模型记住一些新信息。但用 SFT 维护大量、经常变化的知识效率通常很低，还可能影响模型原有的能力。想让模型使用公司内部文档，通常更适合用检索方法。后训练主要调整模型的行为。

03 · 第一种 人写的示范

SFT：还是预测下一个 token，
通常只让回答部分计算 loss

监督微调（supervised fine-tuning）的核心计算和预训练相同：预测下一个 token，使用交叉熵。典型的指令微调主要改了两件事。

改动一

数据换成对话

从「网上的文章」换成「一个请求 + 一个人想要的回答」，中间用固定的特殊 token 隔开。模型通过反复看到 chat template，逐渐学会 <|assistant|> 之类的符号表示「接下来由助手回答」。

改动二

只让回答部分计入 loss

用户的问题仍然会被模型读取，但只作为上下文。训练目标主要是助手的回答。这样训练能集中优化「看到请求后应该如何回答」，不会同时要求模型模仿用户的提问方式。

实验台loss 算在哪些 token 上

这一步主要训练格式和行为，因此需要的数据比预训练少很多。InstructGPT 的 SFT 数据集约有 1.3 万条人写示范。后来 LIMA 只用 1000 条精选示范，同样证明了高质量小数据的效果。

实际流水线通常先做 SFT：模型先学会按格式回答，后面「让模型自己生成再打分」的方法才更容易采到可用的答案。先做 SFT 不是理论上必需的步骤，但通常能让后续训练更稳定。

04 · SFT 不够的原因

SFT 的三个局限

① 判断好坏，通常比亲自示范容易

写一首更好的诗很难，但在两首诗中挑一首更好的，往往容易得多。只靠示范数据训练时，答案质量明显受示范作者能力的限制。

② 不擅长直接表达「A 比 B 好」

SFT 可以用正确示范间接教模型「不要编参考文献」，但很难直接利用「这个答案比另一个差在哪里」的信息。偏好比较更适合表达这种相对好坏。

③ 训练时看到的前文太理想

训练时，要预测的 token 前面通常是标准答案。实际生成时，前面却是模型自己刚写的内容，可能已经出现偏差。模型缺少从自己的小错误中恢复的训练经验。

这些限制对应两种常见做法：让人比较已有答案，让模型从自己生成的回答中学习。

05 · 零件 人的偏好

奖励模型：
把「更好」压成一个数

要让人打分，必须先解决一个问题：人无法在训练循环中打几百万次分。因此，先训练另一个模型模仿人的偏好，再让它批量打分。这个模型就是奖励模型（reward model, RM）。

数据：同一个问题采两个回答，人只回答一句「哪个更好」。
模型：通常从 SFT 模型开始，把最后的输出层改成只输出一个数。这个数用来表示模型对「这个回答有多好」的判断。

loss = − log σ( r(好答案) − r(坏答案) ) // σ 是 sigmoid，把任意实数压到 0~1

注意，这个公式只使用差值。把所有答案的分数都加 5，loss 完全不变。

σ(Δ)：模型认为
「好的确实更好」的概率

RM 的用处，是把有限的人工比较变成一个可以反复调用的自动打分器。人只标一批偏好对，训练阶段就可以让 RM 大规模地替人排序。

RM 只是人类偏好的代理指标。它在接近训练数据的范围内通常更可靠。模型一旦生成 RM 没见过的内容，分数就可能失真。很多「reward hacking / 刷分」问题的原因就在这里。

06 · 第二种 人的偏好 · 在线

RLHF：自己生成，
按分数更新，用 KL 约束

有了可以打分的 RM，训练循环就可以运行。一个 step 包含四个步骤：

① 采

给定一个 prompt，当前模型生成一个回答。

② 评

RM 给这个回答打分。

③ 约束

用 KL 衡量当前模型和参考模型的差异，从奖励中减去这部分差异。

④ 推

按「分 − 罚」的方向更新参数，提高这个回答出现的概率。

成本的主要来源：典型的 PPO-RLHF 训练需要同时维护四种模型角色。

  • policy：正在训练的模型，有梯度和优化器状态
  • reference：SFT 模型的冻结副本，用来衡量当前模型偏离参考模型的程度
  • reward model：冻结的模型，只用于打分
  • critic / value：同时在训练，用于估计奖励的基准值，减少训练中的波动

再加上每个 step 中间都要做一次完整的自回归生成，一个 token 一个 token 地生成答案。因此 RLHF 的工程成本高、资源占用大，而且对超参数较敏感。

③ KL 限制模型偏离参考模型

KL 衡量当前模型和参考模型的输出分布相差多少。如果只追求 RM 分数，模型可能利用 RM 的漏洞持续刷分。KL 罚项限制这种偏离：提高奖励的同时，不离参考模型太远。

InstructGPT 论文里，一个 1.3B 的 RLHF 模型的输出，被标注员判为优于 175B 的原始 GPT-3。参数量相差一百多倍，这里的优势主要来自更符合用户要求的回答行为。

PPO 是第 ④ 步更新参数的一种具体算法，核心方法是用 clip 限制单步更新幅度。换成其他 RL 算法，上面的训练流程仍然成立。PPO 和 RLHF 不是同一层概念。

07 · 第三种 人的偏好 · 离线

DPO：直接使用
偏好对训练

回顾上面的流程，会出现一个问题：人提供的本来就是「A 比 B 好」，这个方法却先把它压缩成一个 RM，再用 RM 教模型。这个中间步骤能否省略？

DPO（2023）的答案是可以。它不再单独训练 RM，而是直接使用「好答案、坏答案」这一对数据调整模型：相对于参考模型，让当前模型更偏向好答案，而不是坏答案。

推导之后，这个目标可以写成下面的 loss。训练时只需要读取固定的偏好数据，不必在每个 step 里现场生成答案：

loss = − log σ( β · [ log π(好)/πref(好) − log π(坏)/πref(坏) ] )

直觉上，它比较两件事：当前模型相对参考模型，给好答案增加了多少概率，又给坏答案增加了多少概率。前者应该比后者大。训练时需要用当前模型和参考模型分别计算好、坏答案的概率，但没有在线生成，没有 RM，也没有 critic。

省掉了
  • 训练 RM 的整个阶段
  • 训练循环中的自回归生成
  • critic 模型
  • 许多 RL 超参数
代价
  • 固定数据不会随模型同步更新。训练过程中模型会改变，但偏好对仍然来自旧模型，与当前模型的匹配度可能逐渐下降。
  • DPO 只保证「好答案比坏答案更可能」，不保证「好答案本身的概率提高」。实验中常见的情况：两者的概率同时下降，只是好答案下降得慢一些。

第一个代价的解决方法是迭代：训练一轮，用新模型重新采样，重新标注偏好，再训练一轮。Llama 3 采用了这种方法，共进行六轮。这种方法重新引入了「模型自己生成数据」这一步，只是把它移到了训练循环之外。

DPO 家族：都在改同一个 loss 的形状

下面几个名字，大体和 DPO 属于同一类方法（离线、使用偏好信号、不单独训练 RM），主要区别在 loss 的具体设计：

IPO

换掉 log-sigmoid，避免模型持续把差值推向无穷大，进而过拟合偏好数据。

KTO

不要成对数据。单条「这条行 / 这条不行」的反馈也能训练模型。现实中的反馈（点赞点踩）本来就是这种形式。

ORPO

把 SFT 和偏好合并成一个 loss，不需要参考模型，直接从 base 模型训练完成。

SimPO

也去掉参考模型，用「按长度归一化的平均 log 概率」作为隐式 reward，同时减轻「回答越长越容易获胜」的问题。

还有一种方法改变的是第 2 个问题而不是 loss 公式：RLAIF / Constitutional AI 把打分者从人换成另一个模型（给模型一份写好的原则，让它判断）。训练方法本身不需要改变，偏好数据则更容易大规模生成。

08 · 第四种 自己采，再当示范

拒绝采样：最直接的一条，
也是常见的工业方案

做法很简单：

①

给定一个 prompt，模型采样 N 个回答（几个到几十个）

②

用 RM、验证器或人工挑出最好的一个

③

把它当成一条新示范，做一次普通 SFT

④

用新模型再采一轮，回到 ①

训练方法仍然是 SFT，因此比较简单、稳定，也不需要 critic。不同之处在于：示范由当前模型生成，再经过筛选。模型学到的是自己可能写出的回答中较好的那些。因此，这种方法常用作工业后训练的主力环节。Llama 2 和 Llama 3 的后训练都大量使用了这种方法。

实验台增大 N 后，挑到的是更好的回答，还是更会刷分的回答？模拟数据
被挑中那条的 · 打分器给的分
被挑中那条的 · 真实质量
打分器分数 真实质量

用代理分数挑选极值时，代理分数和真实质量可能逐渐偏离。采样池越大，选中「刷分答案」的风险也越高。

拒绝采样和 RL 的差别也体现在这一点：拒绝采样只学习被选中的那一条，其余 N−1 条直接丢弃。RL 还会利用「每条答案比基准好或差多少」的信息。因此，RL 能利用更多信息，但拒绝采样通常更简单、更稳定。

09 · 第五种 机器自动验证

RLVR / GRPO：
用可运行的代码打分

回到 RLHF 的流程，只替换一个部件：打分者从 RM 换成验证器。数学题可以比对最终答案，代码题可以运行单元测试，格式要求可以用规则检查。最简单的 reward 是 0 或 1，也可以使用通过率等更精细的分数。

容易扩规模

题目和标准答案已经存在时，不需要逐条请人比较回答

信号更直接

通过测试通常比「RM 猜人会不会喜欢」更接近任务目标

较难通过表面手段刷分

大量客套话无法让单元测试通过，但验证器设计不完整时仍可能被利用漏洞

GRPO 用组内均值替代 critic

PPO 中的 critic 先估计一个基准，用于判断当前分数是高还是低。GRPO 使用一种更直接的参照：同一个 prompt 一次采样一组（G 个）回答，组内答案互相比较。高于组内平均分的答案被鼓励，低于平均分的被抑制，因此不需要单独的 critic。

优势（简化理解） = 自己这条的分 − 这一组的平均分 // 不再单独训练 critic
实验台一组 8 个回答，组内均值当参照
组内平均分 本步是否有效

这也解释了 RLVR 的数据配方核心：题的难度最好落在模型「不是全对也不是全错」的区间。如果同一组全对或全错，组内答案没有高低差别，无法提供有效的相对奖励信号。

结果奖励也可能让模型逐渐生成更长的推理过程。

当奖励主要看最终答案是否正确时，模型可能发现「先多推几步再答」更容易拿到高分，于是回答逐渐变长。DeepSeek-R1 报告里的响应长度曲线就展示了这种现象：不必逐条人工示范「要写多长」，模型也可能学会投入更多推理步骤。

这类方法需要验证器。数学、代码和形式化推理通常可以自动判定。「写一封得体的邮件」「这个回答是否冒犯他人」难以写成明确规则，仍需要依赖人的偏好。实际流水线通常同时使用两类信号。

10 · 蒸馏的分类

蒸馏描述的是数据来源，
训练算法可以保持不变

蒸馏经常和上面几种方法并列提及，但它不在同一个分类层级：蒸馏改变的是「答案从哪里来」，训练算法保持不变。

黑盒 / 序列级

把强模型的输出当示范

采样一批老师模型的回答，做一次普通 SFT。DeepSeek 发布的 R1-Distill-Qwen / Llama 系列就是这样训练的：使用 R1 生成的约 80 万条样本做 SFT，没有做 RL。

白盒 / logits 级

对着老师的整个分布学

老师模型给出的不是一个 token，而是每个位置上的概率分布，学生模型对这个分布计算 KL。最直接的 token-level 方法要求两边词表对齐。tokenizer 不同时，需要额外做 token 映射、序列对齐或其他跨词表蒸馏方法。关键条件是能获取老师的 logits，不一定需要获取权重。

学生模型学到的内容，很大程度上取决于老师模型展示了什么，以及蒸馏数据覆盖的范围。蒸馏能高效地转移「执行能力」，但能力上限通常受老师模型和数据的限制。这正是验证器方法的价值所在：它的信号来自外部世界，不只来自另一个模型。

11 · 词汇表

这些词，不必靠上下文猜

这里不重复解释 token、loss 这类常用词，只收录会影响理解、但不一定人人熟悉的术语。

KL · KL 散度

衡量两个概率分布的差异程度。本文中，它主要用于限制训练后的模型过度偏离参考模型。

policy · 策略模型

正在生成答案、也正在被训练的模型。RL 语境中的 policy，在本文中等同于「当前模型」。

reference model · 参考模型

训练开始前冻结的一份模型副本。它不更新，只用于衡量当前模型偏离参考模型的程度。

reward model · 奖励模型

模仿人类偏好给回答打分的模型。它给的是代理分数，不等于真实质量的绝对刻度。

critic / value · 价值模型

估计正常情况下可以获得的分数，为实际奖励提供比较基准，减少训练中的波动。

online / offline · 在线 / 离线

在线指训练循环里由当前模型现场生成答案；离线指先准备好固定数据，再集中训练。

verifier · 验证器

用标准答案、单元测试或规则自动检查结果的程序。它比 RM 更直接，但只会检查被明确写进规则的部分。

logits

模型为词表里每个 token 给出的原始分数；经过归一化后，才变成下一 token 的概率分布。

拒绝采样 问题 + 自己采的 N 个里最好的RM / 验证器自己（离线批量采）1（采样时另配 RM） 丢弃 N−1 条信息，N 较大时更容易选中刷分的答案
RM 训练 问题 + （好，坏）人（挑）数据集1 离训练分布越远，可靠性越低。它是代理指标，不是真人判断
RLHF / PPO 只要问题，答案当场采RM自己（在线）4 工程复杂、难以调参，可能刷 RM 的分，通常需要 KL 约束
DPO 家族 问题 + （好，坏）人（挑）数据集2（参考模型可预先算完压到 1） 固定数据可能逐渐和当前模型不匹配，常用迭代采样补充
RLVR / GRPO 问题 + 可自动判对错的标准答案验证器自己（在线，一次一组）2 只覆盖能自动判断对错的任务，题目难度需要精确控制

「典型模型角色数」用于帮助理解，不是固定配置。有些角色可以共享参数、预先计算完成，或分开部署。实际工程成本还取决于模型大小、并行方式和生成量。

三条流水线的三个共同点

  • 常见顺序是先做 SFT。模型先学会按格式回答，后面「模型自己生成再打分」的方法才更容易采到值得奖励的答案。R1-Zero 证明了纯 RL 也能发展出推理能力，但输出可读性差，还会中英文混杂。因此，正式版本重新加入了冷启动 SFT。
  • 有效的流水线通常会迭代。采样、训练、用新模型重新采样，循环进行。模型改变后，旧数据可能逐渐不匹配，定期更新数据通常能带来收益。
  • 偏好信号和验证器可以同时使用。能自动判断对错的任务适合使用验证器。难以写成明确规则的质量标准，仍需要依靠人或模型给出的偏好。

分析一种新的后训练方法时，可以先问三个问题：一条样本是什么形式、谁打分、答案从哪里来。确定这三点后，再分析它具体如何优化。
