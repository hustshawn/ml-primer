给已经懂推理的你

训练 = 推理
+ 两步

你熟悉的前向传播，就是训练的第一步。
剩下要补的，只有「算错多少」和「怎么改」。

推理 前向 → 出 token → 中间结果丢掉
训练 前向 → 算 loss → 反向 → 改权重 中间结果全留着
1

一圈四步，重复一百万次

整个训练就是这四步循环。别的全是「怎么把这四步塞进显卡」的工程问题。

STEP 1 · FORWARD

猜

「今天天气真 ___」
模型输出一整个概率分布。
这一步你已经会了。

STEP 2 · LOSS

对答案

真答案是「好」。
模型给「好」的概率越低，loss 越大。
loss = 惊讶程度。

STEP 3 · BACKWARD

追责

从输出往回问每个权重：
「这次错，你占多少责任？」
答案叫梯度。

STEP 4 · UPDATE

拧旋钮

优化器让每个权重
沿梯度反方向挪一小步
（步长 = learning rate）。

没人教它语法、事实、推理 —— 只压「猜下一个词」这一件事，能力是副产品
2

Loss 就是「有多意外」

唯一要记的公式：loss = −log(正确答案的概率)。猜中了≈0，猜歪了→很大。

推理时你在这里做采样（temperature / top-p）。
训练时你在这里算账。

−log 曲线：越不确定，罚得越狠

训练前期 loss 从 ~10 掉到 ~2 就是模型「学会说人话」的过程。

3

显存账本：训练 ≈ 推理的 8 倍

这是从推理跨到训练最该先看的一页。同一个 7B 模型，bf16：

推理14 GB　·　2 字节/参数
权重 14 空 ＋ KV cache 随并发涨
训练112 GB　·　16 字节/参数
权重 14 梯度 14 fp32 主权重 28 动量 m 28 方差 v 28
前向要的（推理也有） 反向产生的 AdamW 的三份状态

而且这还没算激活值。AdamW 给每个参数额外记两个数（动量、方差），再加一份 fp32 主权重防止小梯度被 bf16 吃掉 —— 这就是 2+2+4+4+4 = 16 字节的来历。

4

第五个吃显存的：激活值

反向传播要用到前向的每一个中间结果，所以前向算出来的东西不能扔。这是你在推理端从没遇到的开销。

它随什么涨？

激活值 ∝ batch × 序列长度 × 层数

把 batch 或 context 翻倍，它就翻倍。长上下文训练之所以贵，主要贵在这里，不在权重。

实践里：OOM 第一反应就是砍 batch

Gradient Checkpointing

只存每层入口，中间的反向时重算一遍。
显存大降，算力多花约 30%。

📌 和你熟的方向正好相反：
推理：用显存换算力（KV cache）
训练：用算力换显存（重算）

6

精度：训练不能像推理那样狂量化

你习惯 int8 / fp4 越小越好。训练不行 —— 梯度是很小的数，低精度会直接把它抹成 0。

算的时候
bf16

动态范围大，不用 loss scaling。今天的默认。
（fp16 范围窄，需要 loss scaling 兜着，容易 NaN。）

存的时候
fp32

主权重和优化器状态用 fp32。
否则一次 1e-7 的更新加到 bf16 权重上 = 什么都没发生。

前沿
fp8

H100 / B200 上已实用，能省一大截，但要选择性使用、盯着数值稳定性。

一句话记：训练要动态范围，推理只要够用的分辨率。

7

四段流水线 —— 和你在推理端见过的模型对上号

同一家的 base / instruct / reasoning 三种权重，就是这条流水线上的三个出口。

① 预训练 Pretraining 万亿 token · 千卡 · 数周 · 千万美元级

只做一件事：猜下一个词。喂大规模语料。这一步形成大部分通用知识和语言能力。

出 base model：只会续写，不会听指令

② 继续预训练 百亿 token 级 · 几十卡 · 几天

灌行业语料、新语言，或者把上下文从 8K 扩到 128K。要系统性吸收大量领域语料时常用这一步；少量新事实也可以通过 SFT / LoRA 写入，只是稳定性和容量有限。

出 领域 base model

③ SFT 指令微调 几千 ~ 几十万条（问，答）对 · 单机 · 几小时

给它示范怎么对话。技术要点：只在「答」的部分算 loss，把 prompt 部分 mask 掉。

出 instruct model：你平时调 API 用的就是它

④ 偏好对齐 / RL 让它答得「好」，而不只是「像」

SFT 主要模仿示范；这一步进一步告诉它什么答案更受欢迎、什么结果能被验证。

  • RLHF（PPO）：人标 A/B 偏好 → 训一个打分模型 → 强化学习。经典但工程复杂，常要同时维护 policy、reference、reward 和 value 等模型角色。
  • DPO：直接拿偏好对训，不要打分模型。简单稳定，入门首选。
  • GRPO / RLVR：答案能自动判对错（数学、代码）→ 让模型自己一题采样多份答案，再按验证结果更新。这是训练 reasoning model 的一条重要路线；推理蒸馏和 SFT 也能把长推理行为迁移到其他模型。
出 chat / reasoning model

＋ 蒸馏 Distillation

大模型生成答案，小模型学着答。你在生产上部署的那些便宜小模型，多半是这么来的。

8

LoRA：常用的低成本微调选择

冻住原权重，旁边挂两个「瘦矩阵」，只训它们。参数量降到 0.1%~1%。

全量微调 7B112 GB+
多卡起步
LoRA≈ 20 GB
A100 单卡
QLoRA≈ 10 GB
4bit 底座 · 游戏卡能跑

能干什么：风格、格式、口吻、领域术语、输出结构。
不擅长什么：稳定灌入大量、频繁更新的知识 —— 这类需求通常考虑继续预训练或 RAG。

推理端：可以 merge 回权重（零额外开销），也可以一个 base 挂多个 LoRA 动态切换。

9

真正的主角是数据

架构决定上限，数据决定你实际拿到什么。微调阶段尤其如此。

去重

重复的样本会被死记硬背，还浪费算力。

配比

代码 / 数学 / 多语言占比，直接决定模型有没有那项能力。

Packing

多条短样本拼满一个 context，别让 padding 白烧 GPU。
≈ 推理端的连续批处理

1000>10万

1000 条精挑的样本，往往打败 10 万条脏数据。

⚠️ 灾难性遗忘

只喂你的领域数据，模型的通用能力会明显退化（会说行话了，但不会聊天了）。 标准做法：掺 5%~20% 的通用数据，并且用低学习率、少 epoch。

10

算力：两个公式就能估成本

你已经会算推理吞吐了，训练也一样简单。

训练
6 × N × D

N = 参数量，D = 总 token 数。
（前向 2NP，反向再 4NP）

推理
2 × N

每生成一个 token 的 FLOPs。
你早就知道这个。

算一遍：7B 模型训 1T token

6 × 7e9 × 1e12 = 4.2e22 FLOPs
H100 bf16 峰值 ≈ 990 TFLOPS，实际 MFU 取 40% → ≈ 400 TFLOPS/卡
4.2e22 ÷ 4e14 ≈ 1.05e8 卡·秒 ≈ 1200 卡·天
→ 256 张 H100 跑 ≈ 5 天

MFU

实际 FLOPs ÷ 峰值 FLOPs。大规模训练能到 35%~55% 就算不错。
这就是训练端的「吞吐指标」，对应你熟的 tokens/s。

Chinchilla 20:1

给定算力，最优的 token 数 ≈ 20 × 参数量。
但今天大家为了推理便宜，故意把小模型训到 100~1000 倍 token（超训）。

11

盯仪表盘：三种 loss 曲线

训练时你 80% 的时间在看这一张图。

✅ 健康

前期陡降，后期缓慢下行。就这样。

⚠️ 卡住 / 过拟合

train loss 还在降但 eval loss 抬头 = 过拟合，该停了。平了不动 = lr 太小或数据太少。

💥 Loss Spike

lr 太大、坏数据、数值溢出。做法：回滚到上个 checkpoint，跳过那批数据。

会坏的地方（按出现频率排）

1. OOM —— 永远第一名。砍 batch → 开 gradient checkpointing → 上 ZeRO/FSDP。
2. NaN —— 查 lr、精度、有没有脏样本。
3. dataloader 喂不上 —— GPU 在等 CPU，MFU 莫名很低。
4. 千卡里挂了一张卡 —— 整个 step 挂掉。checkpoint 频率 = 你能承受亏几小时。
5. straggler —— 一张慢卡决定整个集群的 step time。

动手顺序（照这个来最快）

你已经有推理的底子，前三步会比一般人快得多。

手推一遍反向传播

Karpathy 的 micrograd，两小时。看懂梯度是怎么一层层传回去的 —— 这是唯一必须亲手过一遍的东西。

跑通 nanoGPT

在莎士比亚文本上训 10 分钟，亲眼看 loss 从 4 掉到 1.5，输出从乱码变成像样的句子。四步循环从此不再抽象。

用 HF TRL + LoRA 微调一个 7B

单卡。重点不是效果，是亲手撞一次 OOM，然后靠调 batch / checkpointing / QLoRA 把它压进去。第 3、4 节的账本会瞬间变具体。

多卡：读 ZeRO 论文，跑 FSDP 或 DeepSpeed

这是你和纯推理背景的人拉开差距的地方 —— 你本来就懂通信和拓扑。

做一次 DPO

拿同一批 prompt 对比 SFT 前 / SFT 后 / DPO 后的输出。你会第一次真切感到「对齐」是什么意思。

读真实技术报告

Chinchilla（配比）、Llama 3（工程细节、故障率）、DeepSeek-V3（MoE + fp8 + 并行策略）。这些比教科书有用得多。

先问一句：
这事真的需要训练吗？

按这个顺序试，能停在哪就停在哪：
Prompt → RAG → LoRA → 继续预训练 → 全量训练

实际工作里，很多「我要微调」的问题用前两步就能解决。
训练是最后手段，不是第一反应。
