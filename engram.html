条件记忆 · CONDITIONAL MEMORY

有些事该查，
不该算

神经网络里几乎每个动作都是「算」：做一次矩阵乘法，做一次加权平均。「按地址取一行」这个动作，现在的主流模型基本只在最开头用一次。这一页说明如何把这个动作加回来：哪些内容值得存起来查，哪些内容必须现场算。

现算

给我时间，我能推出来

把「3 × 7」用竖式一步步算出来。慢，但任何数都行，不用事先准备。

vs

查表

这个我背过

「三七二十一」：不算，直接说。快，但只对「事先背过的那些」有效。

人同时使用这两种方式：该记住的内容直接背下来，该推导的内容现场计算。Transformer 的中间层基本只有「现算」，没有按地址直接取出短语记忆的模块。即使「Alexander the Great 是人名」这样应该直接记住的内容，模型也只能靠矩阵乘法逐层推导出来。

Engram 填补的就是这个缺口：加一张巨大的表，把该记住的部分从算力转移到内存。本页只有一条主线：这个「查」的动作如何加入模型，加入之后模型发生了什么变化。

一这个想法
01

输入 embedding 已经是一次查表，但钥匙只有一个 token

input embedding 本来就是一次查表。token ID 是下标，embedding 矩阵是表，E[id] 取出一行。这个过程没有矩阵乘法。从算法上看，这是 O(1) 查找：表变大不会增加查找次数。

问题在于这张表的钥匙只有一个 token。语言里最该直接记住的内容（人名、机构名、固定搭配、套话）几乎都要好几个 token 连在一起才成立。Alexander the Great 是三个 token，模型手上没有「这三个连着」那一行。

同一个动作 · 三处不同

Engram 把 input embedding 这个动作放大：钥匙从一个 token 扩成一个短语，位置从第 0 层挪到中间层。

它是新增的模块，不是把 input embedding 改大。原来的输入 embedding 和输出 unembedding 都没有改动。第 ③ 点会在第 11 节用到：早期同类工作都把表放在第 0 层，挪到中间层才能提前预取。

02

查不到短语时，模型只能逐层重建

「拿不到那一行」会产生这样的后果：给模型输入 Diana, Princess of Wales，把每一层的中间状态翻译成文字读出来，可以看到表示到第 6 层才明确指向这个名字。

这个例子里，前 6 层的可读变化主要是在逐步重建名字。

Wales → 一个地名 → 一个头衔 → 具体是谁。探针显示，模型把不少前层深度用在了识别这个固定名称上。这类局部、静态的模式，本来可以通过查表直接提供。

这不是个别案例。语言里有很多局部、静态、高度定型的内容：人名、地名、机构名、术语、成语、套话。这类内容更适合直接记住。

04

从短语到格子号：先归一化，再哈希

钥匙取的是后缀 n-gram：从当前位置往前数两三个 token，最后一个一定是当前这个 token。这个过程不查任何索引，直接用哈希把它算成下标。

点句子里任意一个 token，看它这一步的钥匙和格子号
先归一化：避免同一个词占用多个格子

分词器为了能无损还原原文，会把语义上同一个词切成好几个不同的 ID：Apple / ␣apple / APPLE 各占一个。对查表来说这是一种浪费：同一个词的记忆被拆到几个格子里，每个格子都学不充分。

因此先做一次归一化（NFKC、小写等），把它们合并到同一个规范 ID 上。

—

在 128k 的分词器上，这一步让有效词表缩小 23%。它不是可选的小优化：去掉这一步，是消融实验中掉分最多的三个改动之一。

再哈希：算出下标，不查索引

哈希的好处是不需要知道这个短语是否存在。给定任意短语都能算出一个格子号，算完直接去取。这也意味着地址只跟 token ID 有关。第 11 节会用到这一点，把 Engram 表放到主机内存，并提前取回当前需要的行。

下标 = 哈希(归一化后的 n-gram) mod 格子总数

哈希不止算一次。27B 的配置是：2-gram 和 3-gram 各算一遍，每种开 8 个不同的哈希头，一共 16 次查表，取出的 16 段向量拼成 1280 维。

哈希函数是一个轻量的乘法-XOR 哈希，每张表的格子数取质数。论文没有给出具体常数，下面演示用的是同一族里的 FNV-1a，仅作示意。

这 16 个格子号 · 上排 2-gram，下排 3-gram

全程没有一次矩阵乘，只有 16 次数组下标访问。从算法上看，表从 5B 涨到 100B，查找次数仍是 16 次。实际延迟还会受缓存和数据传输的影响。

05

碰撞无法避免，只能限制其影响范围

回到问题 B。10¹⁵ 个短语挤进 10⁷ 个格子，两个不相关的短语落到同一格是必然事件。因此，解决办法不是消灭碰撞，而是把单次碰撞的影响限制在部分向量上。这正是开 8 个头的原因。

—

拼出来的向量 · 红色 = 发生碰撞的片段

每个头有自己的表和自己的哈希函数。一个头发生碰撞时，其他头通常仍能提供未碰撞的片段。因此，多头能降低一次碰撞影响整条向量的风险。

有后续工作专门研究了这里的碰撞，结论是碰撞噪声更像一种正则化，而不是纯粹的损失。这条结论不是原论文给出的，仅来自对该后续工作摘要的了解。

06

查到的内容不一定正确，因此加一道闸门

碰撞不是唯一的问题。表里的向量是静态的、跟上下文无关的。即使没有碰撞，一词多义也会取回错误的那个意思。因此，查到的内容不能直接使用，必须先判断：这条记忆是否符合当前的上下文。

判断方法沿用 attention 的机制：当前的 hidden state 作为 Query（它已经经过前面的 attention，带有全局上下文），查到的记忆作为 Key 和 Value。两者的点积得到一个 0~1 之间的标量闸门 α，再与记忆相乘。

α = σ( ⟨ 当前上下文, 查到的记忆 ⟩ / √d )　　输出 = α × 记忆
拖动：这条记忆跟当前上下文有多合

闸门 α
—

这道闸门也能减轻碰撞带来的问题。多头把碰撞的影响分散到部分向量上。上下文闸门再根据当前 hidden state，决定组合后的记忆该保留多少。

闸门之后还有一道很短的因果卷积（kernel = 4），用来补充少量非线性。消融实验中去掉这道卷积，分数只下降一点。它是整个模块里最不关键的部件。去掉闸门本身，分数会大幅下降。

闸门在什么地方会亮

亮的地方有两类：多 token 的专有名词，和固定套话。因为钥匙是后缀 n-gram，闸门亮在某个 token 上，意思是「到这个 token 为止的那个短语被认出来了」，所以亮的位置总在短语结尾。

标出来的短语是论文明确提到的。每个 token 的具体强度只作示意，不是复刻原文热力图的数值。

07

装在哪：残差里多一项，只装在少数层

接入方式很保守：H ← H + Engram(输入)，然后照常经过 Attention 和 MLP/MoE。需要仔细权衡的是装在第几层，这里存在一个两难。

两难

需要插得早，才能在骨干花掉太多深度之前提供局部模式，减少第 2 节那类逐层重建。

又需要插得晚：闸门的 Query 用的是当前 hidden state。插在第 1 层时，hidden state 还没积累起全局上下文，无法准确判断是否该采信这条记忆。

实测的甜区是第 2 层：刚经过一轮 attention，两方面的需求都刚好满足。拆成两份、各放一半，比全部放在同一层效果更好。

不装（基线）1.808
装 1 个 · 第 2 层1.770

08

消融实验显示它存了什么内容

最直接的检验方法：训练过程不变，推理时把这张表的输出整个屏蔽，骨干网络不做任何改动，再看分数还剩多少。

屏蔽后保留的成绩（占原成绩的百分比）

事实型知识大幅下降（TriviaQA 只剩 29%），阅读理解几乎不受影响（C3 还有 93%）。读懂一段给定的文本依靠骨干的 attention。「这个人是谁」这类不看上下文就必须知道的内容，主要存在这张表里。

论文说明：这种事后屏蔽会造成训练和推理不一致，在混合能力的任务上噪声较大，因此只用作压力测试，重点看两个极端分数。

「它存着知识」这个说法，有三处容易产生误解。
01

存储单位是「一个短语 → 一段向量」，不是一条事实。钥匙是表面形式，不是语义。它不知道 Diana 是谁，只是看到 princess of wales 这几个词连在一起，先给出一段向量。这段向量能不能变成答案，仍然要靠后面的骨干处理。

02

一个格子不对应一条知识。碰撞会发生，而且一次要取 16 段拼起来，单个格子是叠加状态，无法从里面单独读出一条事实。因此它跟数据库、知识库是两种不同的东西：不能查询、不能列举、不能逐条核对。

03

它不是唯一的知识存放处。屏蔽之后 TriviaQA 还剩 29%，说明骨干里还保留了一部分知识。FFN 作为 key-value 记忆的机制没有被替换。

更准确的说法是：它存的是「短语的先验」，这些先验恰好是大量事实知识的入口。事实往往挂在专有名词和固定搭配上，而这正是 n-gram 能锁定的内容。

09

额外收益：模型相当于变深了

如果这张表的作用只是「存知识」，涨分应该集中在知识题上。实际结果不是这样：推理题涨得更多。

两个 26.7B 模型，激活参数都是 3.8B，训一样的 262B token。「装了」那个是把路由专家从 72 个砍到 55 个，省下的参数变成 5.7B 的表。

解释可以从第 2 节的逐层变化里找。

Engram 提前提供局部模式后，骨干可以更早处理后面的任务。论文给出了两个证据：

①

把每一层的中间状态直接接到输出头上，衡量它离「能预测」有多近：装了表的模型所有层都更接近，最前面几层差距最大。它更早就完成了特征的构建。

②

逐层比较两个模型的表示相似度：装了表的第 5 层，最接近没装的第 12 层。

因此这张表的收益分为两部分：一部分来自它存下的局部模式（第 8 节），另一部分来自骨干更早完成这些模式的识别。论文用后者解释推理题涨分更多的原因。

同一个逻辑带来的另一个好处

局部依赖交给查表之后，attention 不需要再处理「the Milky Way 是一个整体」这类近距离关系，可以专注于远距离关系。长上下文能力因此提升明显：

32k 长文检索不装装了
Multi-Query 大海捞针84.297.0
多跳变量追踪77.089.0

论文特意做了「同预训练 loss」的对照实验，排除「底模本身更强」这个混淆因素之后，这个差距仍然存在。

记忆和计算是两个独立的旋钮，不能互相替代

既然这张表这么好，是否可以把预算全部给它？不可以。两端都会使效果变差，中间存在一个甜区。

右端 · 全给计算

没有专门的地方放静态模式，只能像第 2 节那样用深度重建。这一端就是今天的常规做法，但在这条曲线上是次优的。

左端 · 全给记忆

记住的内容再多也没有帮助，需要现场推理的任务同样掉分。论文原话：在这个区间里，记忆替代不了计算。

如果不锁定总量

上面那条 U 形曲线是争夺同一份预算的结果。如果不互相争夺，骨干保持不变，只把表持续加大，loss 在 log 尺度上会呈一条直线，也就是幂律关系。这是一个可预测的旋钮：表继续变大，loss 就继续下降，而每个 token 的查找次数不变。

地址可提前算出，这张表不必常驻显存

第 4 节说过：地址只跟 token ID 有关。这是这个方案最实际的好处之一：它为「参数必须常驻显存」这条限制提供了一个例外。

Engram 取哪几行

开跑前就知道

token 序列一旦给定，16 个格子号就已经可以算出来。可以在前面几层计算的同时，提前把这些行传输过来，让传输和计算重叠。

把 100B 参数的表整个丢到主机内存 · 吞吐掉多少
4B 骨干9,031 → 8,858 tok/s−1.9%
8B 骨干6,315 → 6,140 tok/s−2.8%

这个数字成立，原因在于一点：每一步真正需要传输的数据量，只跟「取了几行」有关，与表的总大小无关。表从 5B 涨到 100B，每个 token 仍然只取 16 行。

这还是一个保守的下限：这个实验强制所有读取都经过 PCIe。实际做法会利用短语的 Zipf 分布（少数短语占据绝大多数访问）做多级缓存：热数据放显存，长尾数据放 SSD。

12

它不是什么

01

不是 RAG。没有文档、没有向量检索、没有外部知识库。表里存的是训练出来的参数，跟权重一起学、一起存，钥匙是 token n-gram 不是语义相似度。

02

不是 MoE 的替代品。第 10 节那条 U 形就是答案：最优配比是大部分预算仍然给专家，只拿 20%~25% 给这张表。

03

不等于「更快」。第 9 节那张表是同 FLOPs 下更准，不是同准确率下更快。省下来的算力换成了有效深度，不是速度。

04

不是新想法。N-gram 查表能追溯到 Shannon，把 n-gram embedding 接进网络也有许多前作。新的部分有两点：一是在严格同参数、同 FLOPs 的条件下证明它确实有效；二是不把表放在第 0 层，而是插进中间层，这才使第 11 节的收益成立。

05

名字是借用的。engram 在神经科学里指承载一段记忆的那组神经元及其连接变化。这里借用这个名称指「模型里专门存储静态模式的那块区域」，只是借用名称，不代表两者机制相同。

13

一页装下

01

模型里的「查表」动作基本只有 input embedding 这一处，而它的钥匙只有一个 token。该背下来的东西大多是好几个 token 连在一起的，那一行模型拿不到。

02

拿不到就只能用计算逐层重建：在 Diana, Princess of Wales 这个例子里，表示到第 6 层才明确指向这个名字。

03

Engram 做的事：把 input embedding 的钥匙从一个 token 扩成一个短语，位置从第 0 层挪到中间层。

04

短语的组合数比格子数多 8 个数量级 → 只能哈希，也必须接受碰撞。多头把碰撞的影响分散到部分向量，再由上下文闸门决定组合后的记忆该保留多少。

05

装法是残差加一项，只装在少数层。插得太深，省不下深度；插在第 1 层，闸门判断不准；甜区在第 2 层附近。

06

它存的是短语的先验，不是事实条目。但这些先验恰好是事实知识的入口：屏蔽它后，事实题只剩 29%~44%，阅读理解还有 81%~93%。

07

收益有两份：存的那份，加上把深度还给模型那份。后者更大，所以推理题（BBH +5.0）比知识题（MMLU +3.0）涨得更多，长上下文也跟着涨。

08

争夺同一份预算时，记忆和计算的最优配比是 20%~25% 给记忆，偏向任何一端都会掉分。纯计算是次优的。不争夺预算时，表越大越好，且不增加额外算力。

09

地址确定 → 能提前预取 → 100B 的表可以整个常驻主机内存，吞吐只下降 2%~3%。传输量只看取了几行，不看表的大小。
