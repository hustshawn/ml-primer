1

模型被复制，数据被切分

数据并行（DP）做两个操作：复制模型，切分数据。两个操作作用于不同的对象。

模型 → 被复制

每个 GPU 保存模型的全部权重。4 个 GPU 保存 4 份相同的模型。

所有副本必须一直保持相同。第 3 节说明同步过程。

代价：模型显存总量 × N

数据 → 被切分

DP 把一个 batch 切成 N 片。在一步中，每个 GPU 只处理一片，各片不重叠。每个 epoch 重新 shuffle 数据，因此同一个样本可能分到不同的 GPU。

每个 GPU 处理的是 per-device batch。N 个 per-device batch 合起来是 global batch。

收益：每步处理的数据量 × N

global batch 的计算公式

# 配置中的三个数相乘，得到 global batch
global_batch = per_device_batch × N_gpus × grad_accum_steps
                     ↑                  ↑              ↑
              每个 GPU 的样本数     GPU 数量       单个 GPU 累积几轮
                （空间上切）      （空间上切）      （时间上切）

# 示例：per_device=8，8 个 GPU，accum=4
global_batch = 8 × 8 × 4 = 256   # 优化器每 256 个样本更新一次

per_device_batch 不是 batch size。它只是 global batch 的 1/N。如果 GPU 数量改变而这个值不变，global batch 也会改变。这时必须重新调整学习率（见第 10 节）。

2

数据不能复制

下图显示：如果每个 GPU 处理相同的数据，会发生什么。

如果复制数据，每个 GPU 计算出相同的梯度。

4 份梯度相同，平均值仍是原来的梯度。模型没有得到新的信息，但计算成本增加到 4 倍。

因此，DP 必须给每个 GPU 不同的数据。数据切分后，每个 GPU 计算出不同的梯度。这些梯度的平均值等于一个更大 batch 的梯度。

⚠️ 注意：确认每个 rank 读取不同的数据。常见错误是所有 rank 使用相同的 data sampler（没有设置 DistributedSampler，或者 seed 相同）。这时训练可以运行，loss 也会下降，系统不显示错误。但 8 个 GPU 只完成了 1 个 GPU 的工作。

3

一步训练的四个操作

DP 的一步有四个操作。第 1、2、4 步由每个 GPU 独立完成。第 3 步需要所有 GPU 同步。

DP 平均梯度，不平均权重

DP 不是「每个 GPU 单独训练，最后平均权重」。那是另一种方法，名称是 model averaging 或 local SGD。它的收敛性质与 DP 不同。

DP 在每一步平均梯度。因此，每次更新后各 GPU 的权重相同。训练结束时不需要合并权重。

通信与反向传播重叠

反向传播从最后一层开始计算，因此最后几层的梯度先完成。PyTorch DDP 把参数分成多个 bucket。一个 bucket 的梯度完成后，DDP 立即对它做 all-reduce。同时，反向传播继续计算前面各层的梯度。

这样，通信和计算同时进行，第 3 步的大部分时间与第 2 步重叠。这也是 DDP 比旧的 DataParallel 快得多的一个原因。

4

DP 与单 GPU 大 batch 等价

DP 与单 GPU 大 batch 等价。原因是：梯度的平均值等于平均 loss 的梯度。因此，「4 个 GPU × 每个 8 个样本」与「1 个 GPU × 32 个样本」在数学上相同。

# loss = batch 内每个样本 loss 的平均值（几乎所有框架的默认设置）
L(θ) = (1/32) · Σi=1..32 ℓi(θ)

# 求导是线性运算，因此可以先按 GPU 分组求和，再合并
∇L = (1/32) · Σi=1..32 ∇ℓi
   = (1/4) · [ (1/8)ΣGPU0∇ℓ + (1/8)ΣGPU1∇ℓ + (1/8)ΣGPU2∇ℓ + (1/8)ΣGPU3∇ℓ ]
   = (1/4) · [ g₀ + g₁ + g₂ + g₃ ]
              ↑ 这 4 项是每个 GPU 计算出的梯度

# loss 是平均值，因此 all-reduce 计算平均值，不计算总和
ḡ = mean(g₀, g₁, g₂, g₃) = ∇L    ✅ 数学上是同一个量

因此，PyTorch DDP 默认对梯度取 mean，不取 sum。如果取 sum，梯度会增大到 N 倍。这与把学习率乘以 N 的效果相同。

在上述前提下，DP 与单 GPU 大 batch 计算相同的梯度。

DP 可以缩短每一步的计算时间，也可以让一步处理更多数据。除第 5 节中的情况外，DP 不改变优化轨迹。DP 不减少单个 GPU 上的模型状态显存。

5

等式不成立的情况

上面的推导有一个前提：每个样本的 loss 只与这个样本有关。大多数情况下，这个前提成立。在下面三种情况中，它不成立。这些情况不显示错误，但多 GPU 的结果与单 GPU 的结果不同。

BatchNorm

BN 在 batch 内跨样本计算均值和方差。数据切分后，每个 GPU 只用自己的 8 个样本计算统计量。这个值与单 GPU 用 32 个样本算出的值不同。

解决方法：使用 SyncBatchNorm，它对统计量也做 all-reduce。代价是多一轮通信。

CNN 中最常见的问题

LayerNorm / RMSNorm

LayerNorm 和 RMSNorm 只在单个样本的特征维上做归一化。它们不使用 batch 中其他样本的数据。

因此，batch 的切分方式不影响统计量。Transformer 通常使用 LayerNorm 或 RMSNorm，因此没有 BatchNorm 的这个问题。

不受 DP 影响

跨样本 loss

在对比学习（CLIP / InfoNCE）中，一个样本的 loss 把 batch 中的其他样本用作负例。数据切分后，每个 GPU 只有 1/N 的负例。

结果：有效负例数减少到 1/N，模型效果下降。解决方法：先用 all-gather 收集所有 GPU 的 embedding，再计算 loss。

对比学习必须处理

第三种情况：各 GPU 的 batch 大小不同

all-reduce 计算的是「各 GPU 平均值的平均值」。只有各 GPU 的样本数相同时，这个值才等于全局平均值。

以下情况会使各 GPU 的样本数不同：最后一个 batch 不满；按 token 数动态组成 batch。这时，样本少的 GPU 上的每个样本得到更大的权重。要避免第一种情况，设置 drop_last=True。要避免第二种情况，在变长序列训练中按 token 数做归一化，不按样本数做归一化。

7

ZeRO / FSDP：数据切分方式不变

ZeRO 和 FSDP 切分模型状态，但它们仍然属于数据并行。原因是：它们切分数据的方式与 DP 完全相同。它们只改变模型状态的存放位置。

ZeRO 先切分优化器状态

优化器状态占用的显存最多。使用 bf16 混合精度和 Adam 时，每个参数需要保存：

2 B 权重 + 2 B 梯度
+ 4 B fp32 主权重
+ 4 B 一阶动量 m
+ 4 B 二阶动量 v
= 16 B / 参数

3 项 fp32 数据共 12 B，占 四分之三。只有第 4 步（更新）使用这些数据。在其他步骤中，它们占用每个 GPU 的显存，但不被使用。ZeRO-1 切分这部分数据，几乎不增加通信。

代价：ZeRO-3 的通信从 2P 增加到 3P

ZeRO-1 / ZeRO-2 的通信量与纯 DP 相同（都是 2× 参数字节）。一次 reduce-scatter 把梯度汇总到负责该部分的 GPU。一次 all-gather 把更新后的权重发给所有 GPU。显存减少，通信不增加。

ZeRO-3 增加一项通信：每个 GPU 只保存一部分权重，前向计算每一层之前都要 all-gather 权重。总通信量约 3× 参数字节，是纯 DP 的 1.5 倍。

按 ZeRO-1 → 2 → 3 的顺序选择。显存足够时，使用较低的级别
8

梯度累积 = 时间上的数据并行

只有一个 GPU 时，也可以得到大的 global batch。方法是把切分从空间移到时间：一个 GPU 连续做 N 次前向和反向，然后更新一次。如果 loss 归一化、随机数和跨样本运算相同，两种方法得到相同的平均梯度。

# 梯度累积：正确缩放 loss
for step, batch in enumerate(loader):
    loss = model(batch).loss / ACCUM   # ← 不除以 ACCUM，梯度增大到 ACCUM 倍
    loss.backward()                   # 默认把梯度累加到 .grad
    if (step + 1) % ACCUM == 0:
        optimizer.step()
        optimizer.zero_grad()

除以 ACCUM 与 DP 中 all-reduce 取 mean 的作用相同：把总和变为平均值。DP 在 GPU 之间做，梯度累积在时间上做。如果模型有 BatchNorm 或跨样本 loss，或者两种方法使用不同的随机数，结果可能不完全相同。

⚠️ 注意：同时使用 DP 和梯度累积时，在前 ACCUM−1 轮使用 no_sync() 跳过 all-reduce，只在最后一轮同步。如果不这样做，每次更新要做 ACCUM 次全集群通信，训练会变慢。

9

通信量：增加 GPU 时，每个 GPU 的通信量几乎不变

如果 N 个 GPU 两两同步，通信量与 N² 成正比。ring all-reduce 避免了这个问题：每个 GPU 发送的字节数几乎与 N 无关。

P = 梯度的字节数。N 增大时，(N−1)/N 接近 1。因此，在 8 个 GPU 和 8000 个 GPU 上，每个 GPU 每步的通信量几乎相同。这个性质使 DP 可以扩展到几千个 GPU。

通信量不随 N 增加，但仍然很大

7B 模型的 bf16 梯度 = 14 GB。每步每个 GPU 收发约 28 GB。这些数据必须在一步内传完，否则 GPU 等待通信。

因此，训练集群需要高速网络：机内使用 NVLink（数百 GB/s），机间使用 InfiniBand / EFA。如果 DP 组使用普通以太网，通信会成为瓶颈。

最慢的 GPU 决定每一步的速度

all-reduce 是集合操作：所有 GPU 都完成后，操作才结束。因此，每一步的用时 = 最慢 GPU 的用时。

以下问题会使一个 rank 变慢：GPU 降频、网线故障、数据加载慢。这时，整个集群等待这个 rank。集群越大，出现慢节点的概率越高。这是大规模训练最主要的工程问题。

DP 组越大，长尾延迟的影响越大
10

DP 的扩展上限：critical batch size

增加 DP 的 GPU 数量会增大 global batch。batch 超过 critical batch size 后，增加 GPU 通常不再减少收敛所需的步数。

第一点：batch 改变时，必须调整学习率

batch 增大后，梯度噪声减小。因此，可以使用更大的学习率，也需要使用更大的学习率。常用的起点是 linear scaling rule：batch 乘以 k，学习率也乘以 k。训练开始时，使用几个 epoch 的 warmup，因为训练初期的大学习率会使训练发散。

Goyal 等人在 2017 年使用这条规则，把 ResNet-50 / ImageNet 的 minibatch 从 256 增大到 8192。他们在 256 个 GPU 上用 1 小时完成训练，精度与小 batch 基线相同。从 8 个 GPU 扩展到 256 个 GPU，扩展效率约 90%。（Accurate, Large Minibatch SGD, arXiv:1706.02677）

结论：更换集群后，重新调整学习率。例如，从 8 个 GPU 改为 64 个 GPU，per-device batch 不变，global batch 增大到 8 倍。如果使用旧的学习率，训练可能发散，也可能收敛很慢。「相同代码在新集群上不收敛」的问题，最常见的原因是这个。

第二点：batch 超过临界值后，增大 batch 没有收益

梯度包含信号和噪声。batch 小时，噪声占主要部分。增加样本可以显著改善梯度方向，因此增加 GPU 可以加快收敛。batch 足够大时，平均已经消除了大部分噪声。再增加样本几乎不改善梯度方向，只增加每一步的计算量。这个转折点称为 critical batch size。（An Empirical Model of Large-Batch Training, arXiv:1812.06162）

global batch 达到临界规模后，剩余 GPU 通常用于 TP 和 PP。

global batch 达到临界点后，继续增大 DP 度数收益很小。这时，把更多 GPU 用于切分模型。这是 3D 并行（DP × TP × PP）的来源：

critical batch size 限制 DP 度数 → 其余 GPU 用于 TP 和 PP。

推理中通常不使用「数据并行」这个名称

常用的名称是多副本 / replica / 横向扩容。它的工作方式接近无状态 Web 服务的扩容：启动 N 个进程，在前面放一个 LB。

首先确认一个 GPU 能否放下整个模型。能放下 → 启动 N 个副本（吞吐量最高，故障隔离最好）。放不下 → 使用 TP 切分模型。

优先使用多副本，必要时使用 TP

MoE 是一个例外

vLLM 等引擎有 --data-parallel-size 参数。在 MoE 模型上，这个参数不只是启动副本：在 attention 层，每个 rank 处理自己的请求（DP）；在专家层，使用专家并行（EP），token 通过 all-to-all 发送到保存对应专家的 GPU。

这时 DP rank 之间有通信。通信的原因是 MoE 的专家路由，不是数据并行。

只适用于 MoE 模型

14

七个要点

本页内容归纳为以下 7 点。

01

模型被复制，数据被切分。「数据并行」中的「数据」指被切分的对象。

02

每个 GPU 必须读取不同的数据。如果每个 GPU 读取相同的数据，梯度也相同，平均后没有新的信息。

03

一步只有一个同步点：反向传播后，all-reduce 计算 N 份梯度的平均值（不是总和）。这一步使 N 份模型一直保持相同。

04

前提成立时，DP 与单 GPU 大 batch 得到相同的平均梯度。4 个 GPU × 8 个样本对应 1 个 GPU × 32 个样本。BatchNorm、跨样本 loss、随机数和浮点归约顺序可能使实际数值不同。

05

纯 DP 不减少单个 GPU 的模型状态显存。要分摊显存，使用 ZeRO/FSDP（切分状态）、TP（切分矩阵）或 PP（切分层）。

06

增加 GPU 会增大 global batch，因此必须重新调整学习率（linear scaling + warmup）。超过 critical batch size 后，增加 GPU 通常不再缩短收敛时间。

07

推理没有梯度，因此没有训练中的 all-reduce。推理通常使用「多副本 + 负载均衡」。调度器根据请求动态组合 batch。

训练和推理的差别

训练中，每步一次 all-reduce 使 N 个 GPU 成为一个逻辑设备，一起执行同一步。
推理中，N 个 GPU 作为 N 个独立服务处理请求。

是否需要同步梯度，决定了两种系统的结构。
