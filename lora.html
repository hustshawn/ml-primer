它跟「训练」是什么关系

很多人把 LoRA 当成一个训练阶段的名字，跟 SFT、DPO 并列。不是。它们是两个互不干扰的轴。

轴一 · 你在教它什么

这一轴决定 loss 长什么样、数据长什么样。继续预训练是「接着读书」，SFT 是「照着示范做」，DPO / RLHF 是「按偏好打分」。这是训练的目标。

轴二 · 参数怎么被改

这一轴决定 哪些数字有梯度。全量微调 = 全都有；LoRA = 只有旁挂的两条有；冻结全部 = 一个都没有（那就只是推理）。这是训练的手段。

所以「用 LoRA 做 SFT」「用 LoRA 做 DPO」都是正常说法 —— LoRA 是横着切的那一刀，跟你在训什么目标无关。 唯一不成立的是最后一行：LoRA 的整个前提是「底模已经会了，你只要小改」，从零开始没有「小改」可言。

先看全量微调的账单

不看这张账单，就不会明白 LoRA 到底省在哪。7B 模型、bf16 混合精度、AdamW —— 显存大概是这样分的。

注意红色那三条

84 GB 里没有一个字节是「模型」。它们全是「为了知道下一步该怎么改」而存的东西 —— fp32 主权重是为了小步累加不被 bf16 精度吃掉，m 和 v 是 Adam 给每一个参数各配一份的记账本。

换句话说：优化器状态是按「可训练参数个数」收费的，跟模型多大没直接关系。

LoRA 的全部聪明之处就在这一句：如果可训练参数从 70 亿变成 2000 万，这三条红条就自动缩到几乎为零 —— 灰条（冻住的底模）你还得存，但那只是 14 GB，单卡装得下。

原论文在 GPT-3 175B 上量到的正是这件事：训练显存从 1.2 TB 降到 350 GB（省掉的就是冻住那部分的优化器状态）， 约为 1/3。

3

凭什么可以只训两条

因为微调真正需要的「改动量」很扁 —— 一个 4096×4096 的改动，往往只需要几个方向就能描述完。

直觉版：底模已经是个见过整个互联网的通才，你要它「说话客气点、输出固定 JSON、认识你公司的黑话」—— 这些要求相对它已有的能力，是一层很薄的偏置，不是一次世界观重建。薄东西用瘦矩阵就能表示。

4

机理：前向多走一条支路

原来一层线性变换是 h = W₀x。LoRA 之后变成 h = W₀x + (α/r)·B(Ax)。就这一个加号。

为什么先降到 r 维

因为「先压扁再展开」就是低秩的意思。任何 B·A 的秩最多是 r —— r 就是你给这层改动量的预算上限。

为什么不直接改 W₀

改了就得为整个 W₀ 记优化器状态，账单又回到第 2 节那 112 GB。分开放，是为了让「可训练」这个属性只落在小东西上。

算力多花了多少

多两次矩阵乘，但 r ≪ d，属于零头。论文在 GPT-3 175B 上量到 LoRA 训练比全量快 25%（32.5 → 43.1 tokens/s per V100）。

5

为什么第 0 步不掉分

A 随机初始化，B 初始化成全零。这个细节比它看起来重要得多。

这叫「从恒等变换出发」

如果 A、B 都随机初始化，那么训练一开始 ΔW 就是一堆噪声 —— 你等于在一个已经被随机扰乱过的模型上做微调，头几百步全在修自己造的伤。

B 归零保证：第 0 步的 LoRA 模型 = 底模。loss 从底模的水平开始降，而不是先爬回来。 （只让 A 归零不行 —— 那样 A 的梯度也会是零，支路永远长不出来。）

原论文：A 用高斯随机、B 用零。peft 的默认实现里 A 是 kaiming_uniform_、B 是 zeros_（也可以传 init_lora_weights="gaussian" 换成高斯）—— B=0 这条从没变过。

7

α 到底是个啥

支路输出会先乘一个 α/r 再加回主路。α 是「补丁的音量旋钮」。

为什么要除以 r

r 越大，B·A 里累加的项越多，输出天然越大。除以 r 是为了把这个规模差抹平 —— 让你改 r 的时候不用重调学习率。这正是论文写的原意：α 是「一个与 r 无关的常数」， 他们直接把 α 设成第一次试的那个 r，之后就不动了。

论文还有一句很实用的观察：在 Adam 下，调 α 差不多等于调学习率。 所以别同时猛调这两个，会互相掩盖。

常见取法：α = r（缩放 = 1）或 α = 2r（缩放 = 2）。QLoRA 论文用的是 r=64、α=16，缩放只有 0.25 —— 说明它不是必须 ≥1 的东西。

2023 QLoRA：只挂 q,v 追不上全量

QLoRA 论文直接点名了这件事：沿用「只挂 query 和 value」的常规做法， 在大底模上复现不出全量微调的效果。他们在 LLaMA 7B + Alpaca 上发现：

最关键的超参不是 r，而是一共挂了多少个 adapter； 必须挂到 transformer block 里全部的 linear 层才追得上全量微调。 而且一旦挂全了，r 取多少对最终效果几乎没影响。

所以今天的默认答案是：全挂。
q_proj, k_proj, v_proj, o_proj,
gate_proj, up_proj, down_proj

通常不挂：embedding、lm_head、LayerNorm/RMSNorm。 如果你加了新 token，那 embedding 和 lm_head 要另外单独处理，不是 LoRA 的活。

9

训练时，一步里究竟发生了什么

这一节是最多人搞错的地方：反向传播照样要穿过整个冻住的网络。LoRA 没让它变短。

一句话记住这节：LoRA 省的是「记账的钱」，不是「算账的钱」。 forward 和 backward 该跑多少还是多少，只是不用再为 70 亿个参数各准备一套 Adam 记账本。

推理时怎么工作

训完你有两个选择，取决于你要伺候一个客户还是一百个。点一下切换。

可交互 · 推理两种模式
0 额外延迟
推理开销
1 个 adapter
一份显存能服务几个版本

一个容易踩的坑：QLoRA 训出来的 adapter，不要直接 merge 进 4bit 底座。 merge 是加法，加到已经量化过的权重上会把量化误差固化进去。 正确做法是把 adapter merge 进原始 fp16/bf16 底模，或者干脆不 merge、按上面右边那条路服务。

论文里「unlike adapters, no additional inference latency」说的就是左边这条路 —— 早期的 adapter 方法在层里插了额外的串行模块，没法 merge 掉，batch=1 时延迟明显上升；LoRA 因为是并联的线性支路，可以直接加进权重。

# peft + TRL，单卡 QLoRA 微调一个 7B。装的是流程不是魔法。
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer, SFTConfig
import torch

# 1. 底模按 4bit 载入（想用普通 LoRA 就删掉 quantization_config）
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # QLoRA 的 NormalFloat4
    bnb_4bit_use_double_quant=True,          # 连量化常数也量化
    bnb_4bit_compute_dtype=torch.bfloat16,   # 存 4bit，算 bf16
)
model = AutoModelForCausalLM.from_pretrained(BASE, quantization_config=bnb, device_map="auto")
model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)

# 2. 这就是全部的 LoRA 配置
cfg = LoraConfig(
    r=16,
    lora_alpha=32,                          # 缩放 = α/r = 2
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj","k_proj","v_proj","o_proj",
                    "gate_proj","up_proj","down_proj"],   # 全部 linear
)
model = get_peft_model(model, cfg)
model.print_trainable_parameters()   # → trainable: ~40M || all: ~6.7B || 0.6%

# 3. 训。注意 lr 是 2e-4 这个量级，不是 2e-5
SFTTrainer(
    model=model, train_dataset=ds,
    args=SFTConfig(
        learning_rate=2e-4, num_train_epochs=2,
        per_device_train_batch_size=4, gradient_accumulation_steps=8,
        bf16=True, gradient_checkpointing=True,
        lr_scheduler_type="cosine", warmup_ratio=0.03,
        output_dir="out",
    ),
).train()

model.save_pretrained("my-adapter")   # 存下来的只有 A、B —— 几十 MB

# 4. 上线：要么合进原始 bf16 底模，要么保留旁路挂多个

# merged = PeftModel.from_pretrained(base, "my-adapter").merge_and_unload()

print_trainable_parameters() 是第一个该看的输出。 如果它打出来的是 0.06% 而不是 0.6%，说明 target_modules 只匹配上了一部分层 —— 名字写错了，模型不会报错，只会训得很差。

12

能干什么，干不了什么

分界线其实很清楚：LoRA 改的是行为方式，不是知识储量。

适合

· 口吻、人格、语气
· 固定输出格式（JSON schema、报告模板）
· 领域术语和行话的正确用法
· 特定任务的解题套路（分类、抽取、改写）
· 让小模型模仿大模型在某个窄任务上的表现
· 让模型稳定地遵守某套业务规则

共同点：底模其实都会，只是默认不这么做。你在调整倾向，不是灌输。

不适合

· 灌大量新事实（公司 wiki、产品文档）→ 用 RAG
· 要求答案永远最新 → 用 RAG
· 教一门底模基本没见过的语言 / 编程语言 → 继续预训练
· 把上下文从 8K 扩到 128K → 继续预训练（改的是位置编码那一套）
· 从零训一个模型 → 低秩假设不成立

为什么灌知识不行：知识存在整个 W 的分布里，你只给了 r 个方向的预算。 硬灌的结果通常是「语气学到了、事实记串了」。

先爬梯子，别一步跳到微调

0改 prompt成本几分钟。80% 的「模型不听话」到这一步就解决了。
1few-shot 示例把你想要的格式直接摆给它看。比训一版模型快一万倍。
2RAG缺的是「知道」而不是「会做」，就该在这一层解决。
3LoRA / QLoRA前三层都试过、还是差一口气的时候。要有数据、要有评测。
4继续预训练真的要装新知识、新语言、新上下文长度。要几十上百 GB 语料。
5全量微调LoRA 试到 r=128 还追不上，且你有多卡。很少走到这里。

顺序不是「越往下越高级」，是越往下越贵、越难回退。跳级的代价通常是：花两周训了个 adapter，发现改 prompt 就能达到同样效果。

LoRA 家族，一句一个

名字很多，但都在动同一个公式里的某一处。知道它动的是哪一处就够了。

名字
改了哪里
什么时候值得看一眼
QLoRA
底模压成 4bit（NF4 + 双重量化 + paged optimizer），LoRA 本身不变
显存不够。论文做到了单张 48GB 卡微调 65B，Guanaco 在 Vicuna benchmark 上达到 ChatGPT 的 99.3%，单卡训 24 小时。
rsLoRA

DoRA
把预训练权重拆成「幅度」和「方向」，方向交给 LoRA，幅度单独学一个参数
peft 自己的说明：能提升 LoRA 效果、小 r 时尤其明显，但开销比纯 LoRA 大，推理前建议 merge。use_dora=True
LoRA+
给 A 和 B 用不同的学习率（B 更大）
收敛慢的时候可以试，改动极小。
PiSSA / OLoRA
A、B 不再随机初始化，而是从 W₀ 的主成分出发（PiSSA 用主奇异向量），同时把这部分从冻住的权重里减掉

多 LoRA 服务
推理侧的事：一份底模同时挂 N 个 adapter，按请求路由
你要给很多租户各一版模型。vLLM 这类推理引擎已经内建支持。

实务建议：先用最原始的 LoRA 跑通全流程、建好评测，再考虑换变体。 没有评测的话，你根本分不清 DoRA 带来的是提升还是随机波动。

整页压成四句

1 · LoRA 不是训练阶段，是「哪些参数有梯度」这一层的选择 —— 跟 SFT / DPO 正交，可以任意组合。

2 · 机理只有一个加号：h = W₀x + (α/r)·BAx。W₀ 上锁，A 随机、B 归零（所以第 0 步等于底模）。

3 · 省的是优化器状态和梯度，不是 activation、不是反向传播 —— 长序列该 OOM 还是会 OOM。

4 · 推理要么 merge 掉换零开销，要么保留旁路换热切换。二选一，看你伺候一个客户还是一百个。
