1

激活值就是「中间结果」

神经网络前向传播就是一串函数套函数。每经过一层，都会多出一个张量，这个张量就叫激活值。

# 一个模型的前向，本质上就是这样一串赋值
x0 = embedding[token_ids]        # ← 激活值
x1 = layer1(x0)                  # ← 激活值
x2 = layer2(x1)                  # ← 激活值
...
x32 = layer32(x31)               # ← 激活值
logits = lm_head(x32)            # ← 激活值

# 而 layer1 / layer2 里那些 W，是权重。它们从 checkpoint 加载进来，整个前向一动不动。

「激活值」是前向传播中所有中间变量的统称。上面每个 x 都是；每一层内部还有十几个更细的中间量（第 4 节会逐项列出），也都是。

权重属于模型，激活值取决于这次输入。

权重描述模型本身，激活值记录这次前向传播算到了什么。

同一个模型处理两次不同的输入，权重一个比特都没变，激活值却会随输入变化。这个区别也解释了为什么激活值占用会受 batch size 影响，而权重占用不会。

本页使用的符号

形状写成 [B, S, d] 的意思是「这个张量有三个维度，长度分别是 B、S、d」，一共装 B×S×d 个数。再乘上每个数占几个字节（bf16 = 2 字节），就是它占多少显存 —— 这一页所有的显存数字都是这么来的。

B
batch这一次同时喂进去几条序列。你在配置文件里能随手改的那个数。
S
序列长度每条序列有几个 token。训练时就是你设的 context 长度，比如 4096。
d
隐藏维（hidden size）每个 token 在模型内部用几个数表示。Llama-2 7B 是 4096。
L
层数同样的 Transformer 层堆几遍。7B 是 32 层，70B 是 80 层。
H
注意力头数把 d 维切成 H 份，各自独立算一遍 attention。7B 是 32 个头。
d_h
每头维度 = d ÷ H7B：4096 ÷ 32 = 128。现在的模型几乎都是 128 —— 第 6 节会用到这一点。
f
MLP 中间维MLP 先把 d 升到 f 再降回 d。7B 的 f = 11008，比 d 胖 2.7 倍。
d_kv
每个 token 的 K/V 维度KV cache 的大小靠它算（第 11 节）。普通 MHA 下 = d，用了 GQA 就更小。

⚠️ 一个记法上的小陷阱：第 6 节那个业界通用的显存公式沿用论文的小写记法 —— 那里的 s 就是这里的 S、b 就是 B、h 就是 d、a 就是 H。同一批东西，两套大小写，看论文时容易被绕进去。

3

不要和激活函数混淆

「激活值」这个名字来自早期「神经元被激发」的比喻，因此常被误解成激活函数的输出。实际上，它泛指前向传播中的中间张量。

激活函数

ReLU / GELU / SiLU / SwiGLU 那个非线性。它是一个算子，是层里的一个零件。

英文 activation function。

一层里只有一两个

激活值

前向路上任何一个中间张量。Q、K、V、注意力权重、LayerNorm 的输出、残差相加的结果 —— 全都是激活值，跟有没有过激活函数无关。

英文 activations，或者更准确的 intermediate activations。

一层里有十几个

激活值显存

那十几个里，被前向特意留下来、等着反向传播回来取用的那一部分。PyTorch 内部管它叫 saved tensors。

你在显存账本里看到的 activation memory，指的是这个。

这才是花钱的那个

下面这些工程术语里的 activation 都是「激活值」，指的不是激活函数：

activation memory 激活值占的显存   activation checkpointing 少存一些、反向时重算   activation recomputation 同上，同一件事的另一个叫法   activation offloading 把激活值临时搬到 CPU 内存   W8A8 的 A 激活值也量化到 8 bit   activation outlier 激活值里的离群值

5

为什么训练时不能扔

既然算完就该扔，为什么训练时它会堆成几十上百 GB？因为反向传播要回来取它。这一节是全页的因果核心。

看一个最小的例子：一层线性变换

# 前向
y = x @ W          #  x 是这一层的输入（激活值），W 是权重

# 反向：我们要的是 dL/dW，好拿去更新 W
dL/dW = xᵀ @ (dL/dy)
        ↑
        要用到前向时那个 x

# 顺手也把梯度往前传
dL/dx = (dL/dy) @ Wᵀ      # 这个只要 W，不要 x

链式法则的形状就是这样：算权重的梯度，必须知道当时喂给它的输入是什么。逐元素的非线性也一样 —— y = SiLU(x) 的反向是 dL/dx = dL/dy · SiLU′(x)，那个 SiLU′(x) 还得知道 x。

于是前向不能算完就扔，得把 x 留着，一路留到反向走回这一层的那一刻。而反向是从最后一层往前走的 —— 所以第 1 层的激活值，要从前向刚开始一直活到反向快结束。整个网络的激活值几乎同时在显存里。

推理没有反向，所以激活值用完即扔。训练有反向，所以它们全都得排队等着。

这一句就是训练显存和推理显存差那么多倍的其中一个原因（另一个是优化器状态）。

也是「激活值显存」这个词只在训练语境里被反复提的原因 —— 推理侧它几乎不构成问题（第 10 节）。

6

显存账：一个线性项 ＋ 一个平方项

Megatron 团队那篇讲激活值重算的论文，给出了一个业界通用的估算公式。它的形状比它的系数更重要：激活值显存由两项组成，一项随序列长度线性长，一项随序列长度平方长。

# 每层激活值（字节）· 不做任何优化 · 无并行切分
每层 = s·b·h·(34 + 5·a·s/h)  =  34·s·b·h  +  5·a·s²·b
                                   ↑ 线性项        ↑ 平方项
       s = 序列长度   b = batch   h = 隐藏维   a = 注意力头数
       ↑ 就是第 2 节那张符号表里的 S、B、d、H —— 论文用小写，这里跟着论文写

# 34 是这么凑出来的（论文 4.1 节的逐项拆解）
注意力块      11·s·b·h  + 5·a·s²·b   # 后者 = 两个 [B,H,S,S] 张量 + 一个 mask
MLP 块        19·s·b·h                 # 两个矩阵的输入、GeLU 的输入、dropout mask
两个 LayerNorm 4·s·b·h
             ─────────
             34·s·b·h  + 5·a·s²·b

来源：Reducing Activation Recomputation in Large Transformer Models, arXiv:2205.05198，4.1 节。公式对应 GPT-3 式的层（含 dropout、MLP 中间维 4h）；LLaMA 式的层没有 dropout、MLP 是三矩阵 SwiGLU，系数会变，但「线性项 ＋ 平方项」的结构是通用的。

那个平方项什么时候开始压倒线性项？算一下就好

5·a·s²·b > 34·s·b·h
   ⟺   s > 34·h / (5·a)
   ⟺   s > 6.8 × (h/a)
   ⟺   s > 6.8 × 每头维度 d_h

# 现在的模型几乎都是 d_h = 128
临界序列长度 ≈ 6.8 × 128 ≈ 870 个 token

这个结论出奇地干净：它只跟每头维度有关，跟模型多大无关。7B（h=4096, a=32）和 70B（h=8192, a=64）算出来是同一个 870。

也就是说 —— 只要你训练的序列超过大约 900 个 token（也就是所有现代 LLM 训练），激活值显存就由那个平方项主导。这解释了第 4 节那张表里为什么两行就吃掉 73%，也解释了为什么第 8 节那个技术是分水岭。

8

FlashAttention 解决的就是那个平方项

平方项来自「把 S×S 矩阵完整写进显存」，最直接的解法就是：不把它完整写下来。

论文 Theorem 1 的说法是：除输入和输出之外，FlashAttention 只需要 O(N) 的额外显存（N 为序列长度）。反向时它不去显存里读那个矩阵，而是拿保存下来的输出和 softmax 统计量在片上把它重算一遍。速度上的报告是：BERT-large（512）端到端快 15%，GPT-2（1K）快 3×，Long-Range Arena（1K–4K）快 2.4×。（FlashAttention, arXiv:2205.14135）

精确计算，不改变结果

输出和标准 attention 在数学上完全一致，不像稀疏 / 线性 attention 那样改变模型的计算。它能在不牺牲精度的情况下减少显存读写。

这也是它很快成为常用实现的重要原因。

7B / 4K / batch 1：104 GB → 18 GB

GQA 解决的是另一块显存

GQA / MQA 减少的是 K、V 的头数，它显著缩小 KV cache（第 11 节）。但分数矩阵的形状是 [B, 查询头数, S, S] —— 查询头一个都没少。

所以 GQA 对那个平方项几乎没有帮助。FlashAttention 减少这部分激活值，GQA 则缩小 KV cache。

9

重计算：用算力把激活值买回来

还有一条更暴力的路：干脆不存，反向要用的时候现场再前向算一遍。这是显存和算力之间一笔非常划算的交易。

为什么这笔交易划算

它的祖师爷论文（Training Deep Nets with Sublinear Memory Cost, arXiv:1604.06174）给的结论是：n 层网络可以只用 O(√n) 显存，代价是每个 mini-batch 多做一遍前向。他们在 1000 层 ResNet 上把显存从 48 G 压到 7 G，多花了约 30% 的运行时间。

论文还提到极端情况下显存能压到 O(log n)，代价是 O(n log n) 的额外前向计算 —— 一般没人这么干。

显存 ÷ 一大截，时间 × 1.3

选择性重算：只重算划算的部分

全量重算有点浪费 —— 有些张量很大但重算很便宜（比如那个 S×S 矩阵），有些张量不大但重算要走矩阵乘法。那就只重算前一类。

这就是选择性重算（selective recomputation）。Megatron 那篇论文报告：激活值显存降到 1/5，而重算带来的运行时间开销比全量重算减少了 90% 以上。

现在框架里的默认推荐路线 
# PyTorch 里就是一行事
model.gradient_checkpointing_enable()          # HF Transformers
# 或者手写
from torch.utils.checkpoint import checkpoint
h = checkpoint(layer, h, use_reentrant=False)  # 这一段的中间值不保存

⚠️ 两个容易踩的地方：
① 上面那个 1.07 GB 是「存下来的量」，不是显存峰值。重算某一层的时候，那一层的 18 个中间张量还是要临时占一份 —— 峰值 ≈ 1.07 GB ＋ 一层的量。
② 重算会让那段前向跑两次。如果里面有 dropout 之类带随机性的算子，两次的随机数必须一致，否则梯度就错了。框架靠保存并重放 RNG 状态来处理这件事 —— 自己手写 checkpoint 时这是头号 bug 来源。

还有一条路：序列并行。Megatron 那篇论文的另一半贡献是把激活值沿序列维切开，分给张量并行组里的各张卡。LayerNorm、dropout 这些逐位置的算子不需要跨位置通信，因此每张卡不必保存整条序列的激活值。它和重计算可以同时使用。

10

推理侧：用完即扔

推理没有反向传播，所以没有任何人会回来取它。第 5 节那个「全网络激活值同时在显存里」的局面直接消失。

训练：O(层数)

第 1 层的激活值要活到反向快结束。32 层的激活值几乎同时在显存里。

激活值 ≈ 每层的量 × 层数
7B / 4K / b=1 → 18～104 GB

推理：O(1 层)

算完第 2 层，第 1 层的中间值就再也没用了，立刻释放。显存里同时只有一两层的量。

激活值 ≈ 每层的量 × 1～2
同配置 → 几十 MB ～ 几 GB

这就是为什么推理显存账里几乎不提激活值。

推理侧那本账通常只有两项：权重 ＋ KV cache。激活值那点量被四舍五入掉了 —— 除非你在做超大 batch 的 prefill，那时候一层的量本身就很可观（因为 prefill 阶段 S 是整个 prompt 长度）。

但推理侧有一个特例，它是被特意留下来的激活值。下一节就是它。

11

KV cache = 被特意留下来的激活值

如果你已经知道 KV cache 是什么，这一节会让两个概念接上：KV cache 里存的 K 和 V，本来就是第 4 节那张表里的第 03、04 行 —— 普普通通的激活值。它们只是被挑出来，不许扔。

它有多大

2（K 和 V）× L × S × d_kv × 2 字节 × B

d_kv = 每个 token 的 K / V 有多少维。普通 MHA 下它就等于 d；用了 GQA 就小一截。L = 层数，因为每一层都有自己的一份 K/V。

Llama-2 7B（L = 32，d_kv = 4096，MHA）、一条 4096 长的序列：
2 × 32 × 4096 × 4096 × 2 = 2.15 GB。

注意它只随序列长度线性长，没有平方项 —— 因为它存的是 K、V，不是那个 S×S 矩阵。

GQA 直接缩小 dkv

公式里可以直接缩小的是 d_kv。GQA 让多个查询头共享一组 K/V 头，直接把它除掉一个倍数。Llama-2 70B 用 64 个查询头配 8 个 KV 头，KV cache 缩到 1/8。

而第 8 节说过：这对训练时那个平方项没有帮助。两项优化对应不同的显存开销。

GQA → KV cache FlashAttention → 激活值
12

W8A8 里的那个 A

量化命名法 W4A16 / W8A8 里，W 是权重、A 就是激活值。这里有一个很值得知道的不对称：激活值比权重难量化得多，而原因很具体。

权重：可以慢慢挑

训练完就定死了。你可以离线看遍每一个数、算出精确的分布、逐通道挑最优的缩放系数，试一百种方案挑最好的。它不会变。

静态 · 可穷举

激活值：范围依赖输入

每次输入都不一样。通常只能用校准集估计数值范围，而线上输入仍可能超出这个范围。

出现范围外的值时，量化误差会明显增大；LLM 的激活值中确实存在这类离群值。

动态 · 只能估

那些超出范围的值有个名字：activation outlier

LLM.int8() 论文对这类离群值做了量化分析：

  • 出现并不平滑。论文观察到，「跨越所有层的大幅值特征」出现在 6B 到 6.7B 参数之间。
  • 集中在少数维度。在 6.7B 模型上，这些离群值只集中在整个 transformer 的 6 个特征维度里（13B 以内的模型最多 7 个）。
  • 幅度很高。这些维度上的值可达其他维度的 20 倍。
  • 分布范围很广。6.7B 规模上，所有层、约 75% 的序列位置都受影响。

于是 int8 量化直接失效：为了容纳那几个 20 倍大的值，缩放系数被拉得极大，剩下 99.9% 的正常值全被压进极少几个量化格子里，信息就没了。

LLM.int8() 把离群维度单独用 16 bit 计算，其余超过 99.9% 的值走 8 bit。SmoothQuant 使用一个数学上等价的变换，把量化难度从激活值离线转移到权重上（权重更容易量化，见上面左侧），从而让 W8A8 可用；论文报告最高 1.56× 加速、2× 显存下降，并让 530B 模型在单节点内服务。

来源：LLM.int8(), arXiv:2208.07339，4.2 节；SmoothQuant, arXiv:2211.10438。

「权重量化到 4 bit 很常见，激活值量化到 8 bit 就要写论文」—— 差别就在这里。

你在社区里看到的绝大多数量化格式（GPTQ、AWQ、各种 GGUF 的 Q4）都是 W4A16 一类：只量化权重，激活值老老实实用 16 bit。

因为权重量化省的是显存和带宽，代价小收益大；而激活值量化省的是算力（让矩阵乘法真的跑在 int8 单元上），但它要面对上面那 6 个维度。

13

OOM 诊断：先调整哪个参数

最直接的诊断动作是：把 batch size 减半，再看一眼显存。

这个方法依据第 2 节表格的第三行：四块显存里，只有激活值会随 batch 变。所以 batch 减半带来的下降量，可以用来估计激活值在显存中的占比。

⚠️ 一个常见的期望落空：LoRA 不怎么省激活值。LoRA 冻结底模，省掉的是梯度和优化器状态（那是模型状态那一块，往往是大头）。但前向照样要走完整个模型，反向照样要穿过每一层往前传梯度 —— 非线性、attention、SwiGLU 中间值该存的还得存。

（被冻结的线性层确实能少存一点：不算它的权重梯度，就不必为此保留输入。但有 LoRA 旁路的层依然要留。）

因此，用 LoRA 压低模型状态后，显存瓶颈可能转到激活值。这时应考虑 checkpointing 和 FlashAttention，而不是继续调整 LoRA 的 rank。

14

八点总结

下面汇总本页的关键概念。

01

激活值 = 前向路上的中间结果，任何一个中间张量都算。不要和「激活函数」混淆：Q、K、V、注意力权重、LayerNorm 输出全都是激活值。

02

权重属于模型，激活值取决于这次输入。权重保存在 checkpoint 里，激活值不会写入 checkpoint；换个输入就会重新计算。

03

它的形状里带着 batch 和序列长度（[B, S, d]）。这个区别决定了激活值会怎样随输入规模增长。

04

训练时不能扔，因为反向要用。dL/dW = xᵀ·(dL/dy) 里那个 x 就是前向时的激活值。反向从后往前走，所以第 1 层的激活值活得最久 —— 全网络的激活值几乎同时在显存里。

05

显存四大块里，它是唯一随 batch × 序列长度增长的那一块。公式是一个线性项 ＋ 一个平方项：34·s·b·h + 5·a·s²·b（每层）。

06

那个平方项从大约 870 个 token 起就开始主导（临界值 ≈ 6.8 × 每头维度，跟模型多大无关）。它来自 S×S 的注意力分数矩阵；FlashAttention 会避免把这个矩阵完整写入显存。

07

显存不足时可以使用重计算（activation checkpointing）：只存每层入口，其余在反向时重算。经典代价约 30% 额外时间；选择性重算只处理「大而便宜」的部分，可将这项开销减少 90% 以上。

08

推理侧的激活值用完即可释放，所以推理显存账通常只看权重和 KV cache。KV cache 保存的是 K、V 两类激活值。量化里 W8A8 的 A 也是激活值；它比权重难量化，因为 6.7B 以上的模型里有幅度 20 倍的离群维度。

核心概念

激活值是数据流经模型时产生的中间结果。
推理时用完即可释放；训练时要保留到反向传播使用，因此多层激活值会同时占用显存。

训练显存优化中，很大一部分工作都在减少这部分占用。
